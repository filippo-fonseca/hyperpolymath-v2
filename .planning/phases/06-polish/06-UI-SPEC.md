## 1. Visual Mode Taxonomy

Phase 6 overlays TWO visual modes on top of the shared base token set. Every surface belongs to exactly one mode. Mode is determined by route, not by component.

### Mode Definitions

| Mode | Trigger | Character |
|------|---------|-----------|
| **Journal mode** | Default for all data surfaces | EB Garamond, parchment, neumorphic-quiet, neutral-warm accent, monochrome restraint |
| **Agent mode** | JARVIS Console + agent-adjacent pages | Journal base + JARVIS-blue accent + holographic micro-animations + elevated neumorphic depth |

### Route-to-Mode Mapping

| Route | Mode | Rationale |
|-------|------|-----------|
| `/` (JARVIS Console homescreen) | Agent | Central agent surface |
| `/captures` | Journal | Data list — calm, readable |
| `/tasks` | Journal | Data list — calm, readable |
| `/projects/[id]` | Journal | Project detail — document-like |
| `/calendar` | Journal | Calendar grid — functional, clean |
| `/settings` | Journal | Administrative surface |
| `/settings/memory` | Agent | Memory is part of the agent layer |
| `/insights` | Agent | Telemetry over JARVIS activity |
| `/health` | Agent | Diagnostic — JSON surface, Warp-terminal feel |
| `error.tsx` boundaries | Journal | Error fallback stays calm, not dramatic |
| Toasts (all) | Journal | System feedback stays neutral |

**Boundary rule:** Agent-mode styling (JARVIS blue, holographic animations, scan shimmer) MUST NOT appear on Journal-mode routes. A neumorphic button on `/tasks` uses the neutral shadow tokens; the same button on `/insights` may use the agent glow variant.

## 3. Neumorphic Shadow Tokens

All interactive surfaces (buttons, cards, receipt panels, settings tiles, input fields) use neumorphic depth. Body text, list rows, inline metadata, and typography do NOT get neumorphic treatment.

The formula: neumorphism = background color + light offset shadow (lighter than bg, upper-left) + dark offset shadow (darker than bg, lower-right). Restrained — no `filter: blur()` overuse, no hard embossing.

### 3a. Light Theme Shadow Tokens

```css
/* Add to globals.css @theme block */

/* Surfaces — default resting state (cards, panels, receipt containers) */
--shadow-nm-surface:
  4px 4px 10px hsl(38 20% 86%),
  -4px -4px 10px hsl(0 0% 100%);

/* Buttons — resting (convex, slightly extruded) */
--shadow-nm-button:
  3px 3px 8px hsl(38 20% 86%),
  -3px -3px 8px hsl(0 0% 100%);

/* Buttons — hover (slight lift) */
--shadow-nm-button-hover:
  5px 5px 12px hsl(38 20% 84%),
  -5px -5px 12px hsl(0 0% 100%);

/* Buttons — active/pressed (inset — pushed in) */
--shadow-nm-button-active:
  inset 2px 2px 6px hsl(38 20% 86%),
  inset -2px -2px 6px hsl(0 0% 100%);

/* Input fields — inset (concave, receptive) */
--shadow-nm-input:
  inset 2px 2px 6px hsl(38 20% 88%),
  inset -2px -2px 6px hsl(0 0% 100%);

/* Focus ring — journal mode (amber glow) */
--shadow-nm-focus-journal:
  0 0 0 2px hsl(42 18% 97%),
  0 0 0 4px hsl(38 72% 52%);

/* Focus ring — agent mode (JARVIS blue glow) */
--shadow-nm-focus-agent:
  0 0 0 2px hsl(42 18% 97%),
  0 0 0 4px #00d4ff;
```

### 3b. Dark Theme Shadow Tokens

```css
/* Override inside .dark { } block */

/* Surfaces */

/* Buttons — active/pressed */

/* Input fields — inset */

  inset 2px 2px 6px hsl(30 8% 7%),

/* Focus ring — journal mode (amber glow, darker bg) */

/* Focus ring — agent mode (JARVIS blue glow) */

```

### 3c. Neumorphic Application Map

| Component | Shadow Token | Notes |
|-----------|-------------|-------|
| Button (primary/secondary) | `--shadow-nm-button` at rest, `--shadow-nm-button-hover` on hover, `--shadow-nm-button-active` on `:active` | No border; shadow creates edge |
| Card container | `--shadow-nm-surface` | Replace `border` with shadow on settings tiles, receipt panels |
| Receipt panels (JARVIS) | `--shadow-nm-surface` | Retain `border-l` color strip for intent color; shadow on wrapper |
| Input fields | `--shadow-nm-input` | Inset — feels receptive/sunken |
| Settings tile | `--shadow-nm-surface` | Theme tile, memory tile |
| /insights chart panels | `--shadow-nm-surface` | Each chart gets a panel card with surface shadow |
| Sidebar nav items (active) | `--shadow-nm-button-active` (inset) | Active item appears pressed in |
| Focus ring (journal routes) | `--shadow-nm-focus-journal` via `box-shadow` | Use on `focus-visible`, not `focus` |
| Focus ring (agent routes) | `--shadow-nm-focus-agent` via `box-shadow` | Only on JARVIS Console, /insights, /health |
| List rows (Tasks, Captures) | NONE | Rows stay flat — neumorphism on rows = visual chaos |
| Inline type, metadata | NONE | Never apply shadow to text elements |

## 4. Typography Scale

EB Garamond is the ONLY serif typeface. Louize is deferred (D-01). JetBrains Mono is the monospace font, loaded via `next/font/google`. No fallback to system fonts for either after Phase 6 (web fonts loaded in root layout).

### 4a. Full Type Scale

| Role | CSS Class Pattern | Size | Weight | Line Height | Font | Usage |
|------|-------------------|------|--------|-------------|------|-------|
| Display | `text-5xl font-serif font-semibold` | 48px | 600 | 1.1 | EB Garamond | Hero headings (empty states hero text, /insights page title at full bleed) |
| H1 | `text-4xl font-serif font-semibold` | 36px | 600 | 1.2 | EB Garamond | Page headings — Memory, Settings, Insights, Tasks, Captures |
| H2 | `text-2xl font-serif font-medium` | 24px | 500 | 1.3 | EB Garamond | Section headings, card headers, modal titles |
| H3 | `text-xl font-serif font-medium` | 20px | 500 | 1.35 | EB Garamond | Sub-section headings, chart titles |
| Body | `text-base font-serif` | 16px | 400 | 1.5 | EB Garamond | Default body — prose, descriptions, labels |
| Body italic | `text-base font-serif italic` | 16px | 400 italic | 1.5 | EB Garamond | JARVIS prose output, blockquotes, placeholder text |
| Body small | `text-sm font-serif` | 14px | 400 | 1.5 | EB Garamond | Secondary descriptors, settings page sub-copy |
| Caption | `text-xs font-mono text-muted-foreground` | 12px | 400 | 1.4 | JetBrains Mono | Timestamps, receipt metadata, field labels in receipts |
| Badge / label | `text-xs font-mono uppercase tracking-wide` | 12px | 400 | 1.4 | JetBrains Mono | Intent badges (TASK, CAPTURE, EVENT, MEMORY) |
| Code / mono body | `text-sm font-mono` | 14px | 400 | 1.5 | JetBrains Mono | Error digests, /health JSON output, copy-report payload preview |

### 4b. Declared Weights (max 2 — per design constraint)

| Weight | Usage |
|--------|-------|
| 400 (regular) | All body, captions, serif body text |
| 500/600 (medium/semibold) | All headings (H1–H3 use 500 or 600 exclusively) |

H1 and Display use 600 (semibold). H2 and H3 use 500 (medium). The distinction: page titles at 600 communicate authority; section headers at 500 communicate structure without competing.

### 4c. Font Loading

```tsx
// app/layout.tsx — update to add JetBrains Mono
import { EB_Garamond, JetBrains_Mono } from 'next/font/google'

const ebGaramond = EB_Garamond({
  subsets: ['latin'],
  weight: ['400', '500', '600', '700', '800'],
  style: ['normal', 'italic'],
  variable: '--font-eb-garamond',
  display: 'swap',
})

const jetbrainsMono = JetBrains_Mono({
  subsets: ['latin'],
  weight: ['400', '500'],
  variable: '--font-jetbrains-mono',
  display: 'swap',
})
```

Update `globals.css @theme`:
```css
--font-mono: var(--font-jetbrains-mono), "Fira Code", Menlo, monospace;
```

### 4d. Hierarchy Enforcement Rules

- Every page must use exactly one H1. No H1-skipping (H2 before H1).
- JARVIS prose output (`textDelta`) renders as body italic — EB Garamond 16px italic, weight 400. This is the "JARVIS register" visually.
- Metadata rows in receipts (priority, due date, hashtag list) always use the Caption/mono row — never body serif.
- Empty state headings use H2 (not Display) — they must feel calm, not dramatic.

## 6. Motion Specifications

All motion uses `motion/react`. All durations have a `prefers-reduced-motion` fallback. The `useReducedMotion()` hook from `motion/react` is the canonical check.

### 6a. Global Reduced Motion Fallback

Add to `globals.css` (after existing animation declarations):

```css
@media (prefers-reduced-motion: reduce) {
  /* View transitions */
  ::view-transition-old(*),
  ::view-transition-new(*),
  ::view-transition-group(*) {
    animation-duration: 0s !important;
    animation-delay: 0s !important;
  }
  /* CSS animations (shimmer, pulse) */
  .jarvis-queued-shimmer,
  .jarvis-scan-wipe,
  .jarvis-cursor-pulse,
  .rbc-event-placeholder {
    animation: none !important;
  }
}
```

In motion/react components:
```tsx
const shouldReduce = useReducedMotion() // from motion/react
const dur = (n: number) => shouldReduce ? 0 : n
```

### 6b. Duration and Easing Table

| Animation | Duration | Easing | Reduced-motion fallback |
|-----------|----------|--------|------------------------|
| Page transition (template.tsx fade) | 150ms | `easeOut` | 0ms (instant) |
| List item entry (Tasks, Captures) | 200ms | `easeOut` | opacity-only, 0ms |
| List item exit (`AnimatePresence`) | 150ms | `easeIn` | 0ms (instant) |
| Toast in (sonner managed) | 300ms | sonner default spring | fade only at 0ms |
| Toast out (sonner managed) | 200ms | sonner default | fade only at 0ms |
| JARVIS receipt fade-in (`motion.div`) | 200ms | `easeOut` | 0ms opacity only |
| JARVIS receipt y-offset entry | 4px → 0 over 200ms | `easeOut` | No y movement; opacity only |
| Undone tombstone fade | 150ms `opacity` + `grayscale` CSS transition | CSS transition | instant |
| Sidebar item hover | 100ms | `easeOut` | instant |
| Modal enter (shadcn Dialog) | 200ms scale+fade (Radix default) | spring | fade only |
| Error.tsx content fade-in | 300ms | `easeOut` | instant |
| /insights chart bar entry (recharts animation) | 500ms | `easeOut` (recharts `isAnimationActive`) | `isAnimationActive={false}` |
| Queued shimmer (Agent mode) | see §7 | — | CSS animation disabled |
| Streaming cursor pulse (Agent mode) | see §7 | — | static cursor |
| Scan reveal wipe (Agent mode) | see §7 | — | instant opacity reveal |
| Holographic receipt fade (Agent mode) | see §7 | — | opacity only 200ms |

### 6c. Page Transitions

Use `app/(app)/template.tsx` (re-renders on every navigation, unlike `layout.tsx`):

```tsx
// app/(app)/template.tsx
'use client'
import { motion } from 'motion/react'
import { useReducedMotion } from 'motion/react'

export default function Template({ children }: { children: React.ReactNode }) {
  const shouldReduce = useReducedMotion()
  return (
    <motion.div
      initial={{ opacity: 0 }}
      animate={{ opacity: 1 }}
      transition={{ duration: shouldReduce ? 0 : 0.15, ease: 'easeOut' }}
    >
      {children}
    </motion.div>
  )
}
```

No y-offset on page transitions — sliding pages feel disorienting in a dense OS tool. Pure opacity.

### 6d. List Item Animation Pattern

```tsx
// Example for Captures feed, Tasks list
<AnimatePresence initial={false}>
  {items.map(item => (
    <motion.div
      key={item.id}
      layout
      initial={{ opacity: 0, y: shouldReduce ? 0 : 4 }}
      animate={{ opacity: 1, y: 0 }}
      exit={{ opacity: 0, y: shouldReduce ? 0 : -4 }}
      transition={{ duration: shouldReduce ? 0 : 0.2, ease: 'easeOut' }}
    >
      {/* item content */}
    </motion.div>
  ))}
</AnimatePresence>
```

The `layout` prop enables smooth reorder animation when drag-drop changes order in the Tasks kanban.

## 7. JARVIS-esque Animation Specs (Agent Mode Only)

These animations apply EXCLUSIVELY on Agent-mode routes: JARVIS Console, /settings/memory, /insights, /health. They MUST NOT appear on Journal-mode routes.

Reference aesthetics: Iron Man HUD scan lines, Apple Watch "Now Playing" concentric pulse, Linear command palette focus ring intensity.

### 7a. Queued Placeholder Shimmer

**What:** When a receipt slot is in `status: "queued"` (executor in-flight), the placeholder shows a scan-line shimmer moving left-to-right through the JARVIS-blue gradient.

**Current state:** `animate-pulse` (Tailwind default). Replace with a custom shimmer.

**Spec:**
```css
/* globals.css */
@keyframes jarvis-queued-shimmer {
  0%   { background-position: -200% 0; }
  100% { background-position:  200% 0; }
}

.jarvis-queued-shimmer {
  background: linear-gradient(
    90deg,
    transparent 0%,
    rgba(0, 212, 255, 0.10) 40%,
    rgba(0, 212, 255, 0.25) 50%,
    rgba(0, 212, 255, 0.10) 60%,
    transparent 100%
  );
  background-size: 200% 100%;
  animation: jarvis-queued-shimmer 1.8s ease-in-out infinite;
}
```

**DOM application:** The queued receipt `div` gets `className="jarvis-queued-shimmer"` added via `cn()`. Existing `border-l-2` intent color strip is retained. `animate-pulse` removed.

**Reduced motion:** `animation: none !important` per global rule in §6a. The placeholder still renders (border strip, icon, "queued…" label) — just without the sweep.

### 7b. Streaming Prose Caret Pulse

**What:** While JARVIS streams prose (`textDelta` growing), the trailing cursor blinks with a JARVIS-blue pulse. This replaces the browser default text cursor inside the non-editable prose area.

**Spec:**
```css
@keyframes jarvis-cursor-pulse {
  0%, 100% { opacity: 1; box-shadow: 0 0 4px 1px rgba(0, 212, 255, 0.5); }
  50%       { opacity: 0.3; box-shadow: none; }
}

.jarvis-streaming-caret {
  display: inline-block;
  width: 2px;
  height: 1.1em;
  background: #00d4ff;
  border-radius: 1px;
  vertical-align: text-bottom;
  margin-left: 2px;
  animation: jarvis-cursor-pulse 1.1s ease-in-out infinite;
}
```

**DOM:** Rendered as `<span className="jarvis-streaming-caret" aria-hidden="true" />` appended to the prose `textDelta` container while `turn.status === "streaming"`. Remove on `"done"`.

**Reduced motion:** `animation: none`. The caret `span` stays (visible as a static `#00d4ff` bar) — removes the pulse but keeps the visual indicator.

### 7c. Scan Reveal Wipe

**What:** When a new assistant turn "lands" (transitions from streaming → done), a single scan-line sweeps top-to-bottom across the content area, then disappears. One-shot, not looping. Evokes an Iron Man HUD scan completing.

**Spec:**
```css
@keyframes jarvis-scan-reveal {
  0%   { top: 0%; opacity: 0.6; }
  80%  { top: 85%; opacity: 0.4; }
  100% { top: 100%; opacity: 0; }
}

.jarvis-scan-line {
  position: absolute;
  left: 0;
  right: 0;
  height: 2px;
  background: linear-gradient(
    90deg,
    transparent 0%,
    rgba(0, 212, 255, 0.3) 20%,
    rgba(0, 212, 255, 0.7) 50%,
    rgba(0, 212, 255, 0.3) 80%,
    transparent 100%
  );
  pointer-events: none;
  animation: jarvis-scan-reveal 400ms ease-in forwards;
}
```

**DOM:** Inject a `<div className="jarvis-scan-line" />` as a sibling to the turn container when `status` transitions to `"done"`. Use a React key or `useEffect` cleanup to remove after 400ms. The turn container needs `position: relative; overflow: hidden`.

**Reduced motion:** Do not inject the scan line element at all — check `useReducedMotion()` before mounting.

### 7d. Receipt Holographic Fade-In (Agent Mode)

**What:** When a receipt transitions from queued to done on Agent-mode surfaces, the fade-in adds a subtle blue color-wash that resolves to the normal receipt color within 300ms.

**Spec (motion/react):**
```tsx
// Agent-mode receipt mount animation
<motion.div
  initial={{ opacity: 0, y: 4, filter: 'brightness(1.4) saturate(0.3) hue-rotate(160deg)' }}
  animate={{ opacity: 1, y: 0, filter: 'brightness(1) saturate(1) hue-rotate(0deg)' }}
  transition={{
    duration: shouldReduce ? 0 : 0.3,
    ease: 'easeOut',
    filter: { duration: shouldReduce ? 0 : 0.25 }
  }}
>
```

**Reference:** The `hue-rotate(160deg)` briefly shifts the receipt toward blue before resolving to its natural intent color. This is the "JARVIS bringing the element online" visual metaphor.

**Reduced motion:** `initial` and `animate` both set to no-op (opacity 0→1 only, 0ms).

### 7e. Agent Surface Glow (Passive)

## 11. Accessibility Constraints

### 11a. Focus Rings

- **Journal mode routes:** Focus ring uses `var(--shadow-nm-focus-journal)` (amber, 2px ring + 2px gap)
- **Agent mode routes:** Focus ring uses `var(--shadow-nm-focus-agent)` (JARVIS blue, 2px ring + 2px gap)
- Applied via `focus-visible:` pseudo-class only (not `focus:`) to avoid rings on mouse-click
- All shadcn Button, Input, Select components must retain their focus-visible ring — verify `outline-none` is not applied without a replacement `focus-visible:ring-*`
- Minimum focus ring contrast ratio: 3:1 between ring color and adjacent background (WCAG 2.1 §1.4.11 Non-text Contrast)

### 11b. Color Contrast Minimums (WCAG AA)

| Pairing | Ratio Target | Verified |
|---------|-------------|---------|
| `--color-foreground` (hsl 30 8% 16%) on `--color-background` (hsl 42 18% 97%) | ≥ 7:1 (AAA) | High confidence — confirmed by RESEARCH |
| `--color-foreground` (hsl 38 15% 92%) on dark bg (hsl 30 8% 10%) | ≥ 7:1 (AAA) | High confidence |
| `--color-muted-foreground` light on background | ≥ 4.5:1 | Must verify with browser DevTools |
| `--color-accent` amber on background (decorative use) | ≥ 3:1 (large text / UI) | Amber on parchment — verify |
| `#00d4ff` JARVIS blue on dark card bg | ≥ 3:1 (UI element) | Must verify — blue on near-black |
| `#00d4ff` JARVIS blue on light card bg | ≥ 3:1 (UI element) | Electric blue may fail on parchment — use only where bg is dark |
| White on destructive (`hsl 4 72% 42%`) | ≥ 4.5:1 | Must verify |

**JARVIS blue constraint:** `#00d4ff` is optimized for dark backgrounds. On light-theme agent surfaces (JARVIS Console in light mode), verify contrast of JARVIS-blue elements. If they fail 3:1, increase opacity or darken the blue for light mode. Light-mode safe alternative: `#009bb5` (same hue, 70% saturation, 35% lightness).

### 11c. Keyboard Navigation Scope

| Shortcut | Behavior | Implementation |
|----------|---------|----------------|
| `Cmd+K` | Focus JARVIS Console input | `useImperativeHandle` on JarvisInput + module-level `registerJarvisFocus` singleton + window `keydown` listener in `(app)/layout.tsx` or a `GlobalHotkeys` client component |
| `Tab` | Standard tab traversal through all interactive elements | Radix primitives handle this for shadcn components; verify custom elements |
| `Escape` | Close open modals/sheets/popovers | Radix Dialog/Popover handle this natively |
| `Enter` / `Space` | Activate focused button/link | Native `<button>` and `<a>` elements handle this; custom `div[role="button"]` elements must add `onKeyDown` handler |

### 11d. Reduced Motion

All animation behavior at `prefers-reduced-motion: reduce`:
- Page transitions: instant (0ms)
- List enter/exit: instant opacity only
- JARVIS shimmer: disabled (CSS `animation: none`)
- JARVIS cursor pulse: static bar (no animation)
- JARVIS scan reveal: not mounted
- Holographic fade: instant opacity 0→1, no filter
- recharts bar animation: `isAnimationActive={false}`
- Empty state fade-in: instant
- Receipt fade-in: instant

### 11e. ARIA Labeling

| Component | Required ARIA |
|-----------|-------------|
| Theme toggle | `aria-label="Switch to dark mode"` / `"Switch to light mode"` |
| JARVIS streaming caret | `aria-hidden="true"` |
| JARVIS scan line | `aria-hidden="true"` |
| Queued shimmer overlay | `aria-hidden="true"` |
| Empty state container | `role="status"` (content changes reactively) |
| Error page | `<main>` element wrapping |
| /health status badges | `aria-label="Supabase: ok"` etc. |
| Toast undo button | `aria-label="Undo: [action name]"` |

## 13. Non-Goals

This UI-SPEC explicitly does NOT cover:

- **Mobile (<768px):** Out of scope per AES-07 and D-01 in CONTEXT.md. Layout must not break below 768px, but no specific mobile-native UX is specified.
- **Louize typeface:** Deferred to backlog (procurement decision). All heading references use EB Garamond exclusively.
- **CMDK command palette:** Cmd+K scopes strictly to JARVIS Console focus (D-02). No overlay palette.
- **Sentry / PostHog / Highlight:** Explicitly excluded (D-03). Custom clipboard-based error reporting is the spec.
- **Voice UI (mic indicator, wake-word visual):** Phase 7 scope. VOICE-01..14 are out of scope.
- **Full /insights richer dashboard:** Time-range picker, top-N errors table, cache hit rate panel — deferred.
- **Kanban drag-and-drop visual spec:** Phase 2 already shipped `@dnd-kit`. No changes to drag UX in Phase 6.
- **Project detail page redesign:** Journal mode applies. No net-new visual spec needed beyond global typography and neumorphic token adoption.
- **Accessibility beyond WCAG AA:** AAA compliance is aspirational. Specified minimums are AA (4.5:1 for text, 3:1 for UI elements).
- **shadcn third-party registry blocks:** No third-party registry components are introduced in Phase 6. Official shadcn components only. Registry safety gate: not required.
