# Phase 05.1 Plan 02: Prose-First Personality Summary

One-liner: personality.ts inverted from "emit tool calls only" to prose-first (leading text block + tool_use); JarvisScrollback gate dropped so prose renders above receipts on action turns; compact receipt variant and queued SSE placeholder lifecycle added.

## What Changed

### Task 1: personality.ts rewrite + contract tests (JARVIS-20)

**Inverted the core output-format rule (D-R3):**

Phase 5's `personality.ts` contained:
> "OUTPUT FORMAT: when filing (task/capture/event), emit tool calls only. Do NOT prefix tool calls with narrative text..."

This line is now **gone**. The replacement in `TOOL_USE_RULES`:
> "OUTPUT FORMAT: Always emit a leading text block FIRST on action turns (1-3 sentences in JARVIS register summarising what you are about to do), THEN emit the tool_use blocks."

**Calibration target added verbatim to JARVIS_PERSONALITY:**

The canonical example from D-R1 now appears in the system prompt as the model's gold reference:
```
User: "dinner 8pm saturday with anna + remind me to buy flowers friday"
You: [text] "Handled, sir. Dinner with Anna is on the calendar for Saturday at eight,
            and I've added a reminder to pick up flowers on Friday. I'd recommend not
            showing up empty-handed unless your plan is to rely entirely on charm again."
     [create_event] { ... }
     [create_task]  { ... }
```

**D-R4 / Blocker 1 forward-compatibility:**

TOOL_USE_RULES META-QUESTIONS section now explicitly references "JARVIS MEMORY block" — permitting `/ask` mode to answer "what do you remember about me?" once Plan 03 injects the facts block. The literal substring `JARVIS MEMORY` is present and guarded by the new contract test.

**Removed absolutist "Do not ask clarifying questions":**

The old rule is replaced with "capture-first remains the default fallback" while leaving room for Plan 04's `ask_clarification` tool.

**VOICE_ADDENDUM updated:**

Previous: described `voice_summary` field (a two-line receipt model)
New: describes leading text block behavior — the text block IS the spoken response

**New test file `packages/jarvis-core/tests/personality.test.ts` (5 tests):**
- `TOOL_USE_RULES` contains "leading text block"
- `TOOL_USE_RULES` does NOT contain "emit tool calls only"
- `JARVIS_PERSONALITY` contains "Handled, sir" (calibration example)
- `JARVIS_PERSONALITY` has capture-first but NOT "Never ask clarifying questions"
- `TOOL_USE_RULES` contains "JARVIS MEMORY" (D-R4 forward-compat)

**Updated `prompt-builder.test.ts`** to match new personality wording (4 tests updated — not removed; assertions regraded for Phase 5.1 rules).

### Task 2: JarvisScrollback gate drop + compact receipt + queued SSE (D-P3)

**JarvisScrollback gate removal (`JarvisScrollback.tsx`):**

Before:
```tsx
{turn.actions.length === 0 && turn.textDelta ? (
  <div className="font-serif ...">
    {turn.textDelta}
  </div>
) : null}
```

After:
```tsx
{/* Phase 5.1 (D-R1) — render textDelta on every assistant turn that has it */}
{turn.textDelta ? (
  <div className="font-serif text-base text-foreground/90 mb-2 leading-relaxed">
    {turn.textDelta}
  </div>
) : null}
```

Receipts are now passed `variant="compact"` when the turn has prose — visually de-emphasizing them beneath the text.

**JarvisReceipt compact variant + queued placeholder (`JarvisReceipt.tsx`):**

Compact variant Tailwind classes:
```
"rounded my-1 border-l px-2.5 py-1 opacity-95 {meta.classes}"
```
vs default:
```
"rounded my-1 border-l-2 px-3 py-2 {meta.classes}"
```

Body text: `text-xs` in compact vs `text-sm` in default.

Queued placeholder (fires before executor resolves):
```tsx
<div data-status="queued" className="... animate-pulse opacity-60">
  <Icon /> TASK <span>queued…</span>
</div>
```

**jarvis-types.ts — ScrollbackAction extended:**

```typescript
export interface ScrollbackAction {
  toolUseId: string;
  name: "create_task" | "create_capture" | "create_event";
  status?: "queued" | "done";   // ← new
  result?: { ok: true; ... } | { ok: false; ... };  // ← now optional
  undone?: boolean;
}
```

**route.ts — new `event: queued` SSE emission:**

```typescript
// BEFORE the executor async IIFE:
controller.enqueue(encoder.encode(sse("queued", { toolUseId: b.id, name: b.name })));
```

SSE wire protocol now:
```
event: queued  data: { toolUseId, name }  ← new; fires before executor work
event: text    data: { delta }
event: action  data: { toolUseId, name, result }
event: done    data: { usage }
event: error   data: { message }
```

**jarvis-stream-client.ts — `onQueued` callback:**

```typescript
export interface JarvisCallbacks {
  onQueued?: (data: JarvisQueuedEvent) => void;  // ← new, optional
  ...
}
```

**JarvisConsole.tsx — queued→done lifecycle:**

`onQueued` pre-pushes a placeholder action with `status: "queued"`. `onAction` finds the existing placeholder by `toolUseId` and upgrades it in-place to `status: "done"` with the real result — no flicker, no duplicate receipt.

## SSE Wire Protocol Change

**Payload shape:**
```json
{ "toolUseId": "toolu_abc123", "name": "create_task" }
```

**Client handling (jarvis-stream-client.ts):**
```typescript
} else if (eventName === "queued") {
  callbacks.onQueued?.({ toolUseId: ..., name: ... });
}
```

**Timing:** Fires synchronously in the `contentBlock` handler, before the async executor IIFE is pushed to `pendingActions`. Observable as a leading animation on slower calls (gcal events especially).
