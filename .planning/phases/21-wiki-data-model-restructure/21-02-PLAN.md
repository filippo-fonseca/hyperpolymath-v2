<objective>
Rewrite the query + Server Action layer on top of the new schema so the Wiki is organized by an independent folder hierarchy, and compute each node's effective project set with inherited-and-locked flags.

This plan rewrites `getFoldersForUser`/`getFoldersForProject` into project-independent queries that load `folder_projects`, rewrites `buildPagesTree` to assemble a `parent_id` hierarchy with effective project sets via an in-TS ancestor walk, updates the folder + page Server Actions (drop required projectId, add parentId with a cycle guard, write `pages.folder_id` directly), and adds a cross-user RLS integration test for `folder_projects`.

Purpose: Turns the new schema (plan 21-01) into usable query/mutation surfaces and proves owner isolation. This is the data layer phase 23 (tree UI) and phase 24 (linking UX) consume — the isInherited flag is computed here so downstream phases need no schema change.

Output: Project-independent folder queries, a rewritten buildPagesTree, updated Server Actions with cycle prevention, and a passing cross-user RLS test. WIKI-MODEL-04, 05, 06, 07 satisfied.
</objective>
