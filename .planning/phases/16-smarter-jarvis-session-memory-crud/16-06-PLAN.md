Universal 5-second undo on every JARVIS mutation (SMJ-14), replacing 16-05's creates-only triple-gate with capability-based gating. Undo `create_*` → delete (existing behavior, unchanged). Undo `update_*` → restore the `before` snapshot of changed fields. Undo `delete_*` → recreate the entity from a pre-delete row snapshot.

Purpose: Match the existing mobile 5s undo and Phase 5's per-receipt undo countdown across all JARVIS actions, so any mistaken JARVIS edit is reversible within the same 5s window the user already knows.

Output: Executor methods enriched with inversion payloads (`before` / `snapshot`); `undoJarvisActionForUser` extended with six new inversion kinds; frontend gating switched from name-prefix to capability; Vitest coverage for all six inversion paths + cross-user blocking.
