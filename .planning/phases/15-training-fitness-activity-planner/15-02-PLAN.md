Create `apps/web/app/actions/training.ts` starting with `"use server";`. Mirror the file structure of `apps/web/app/actions/tasks.ts`.

Required exports:

**Auth helper:**
- `async function getUserId(): Promise<string | null>` using `supabase.auth.getClaims()` exactly per Pattern in RESEARCH (NEVER `getSession`).

**Discriminated result type:**
- `type ActionResult<T> = { success: true; data: T } | { success: false; error: string }`.

**Batch actions:**
- `createBatch(input)` — Zod: `{ id?: uuid, name: string≥1, description?: string }`. Insert with computed `orderIndex = MAX(orderIndex)+1` for this user.
- `updateBatch(input)` — `{ id, name?, description? }`. Verify row.userId === userId before update.
- `deleteBatch({ id })` — set `archivedAt = now()` (soft delete; activities orphan-to-null via FK ON DELETE SET NULL is on type, batches just archive).
- `reorderBatches({ orderedIds: string[] })` — update `orderIndex` for each in order, all within a Drizzle transaction. Verify all ids belong to user.

**Type actions:**
- `createType(input)` — Zod: `{ id?, batchId?: uuid|null, name: ≥1, color: string (regex `^oklch\(`), hasDistance: boolean }`. Verify `batchId` (if non-null) belongs to userId.
- `updateType({ id, ...fields })` — same fields, all optional.
- `deleteType({ id })` — soft delete via `archivedAt`. Check count of non-archived activities referencing it; if > 0, return `{ success: false, error: "This type has N activities. Archive instead." }` (per RESEARCH Open Question 4 / D-04 manage flow). Allow archive even if activities exist.
- `reorderTypes({ orderedIds, batchId? })` — update `orderIndex` within transaction.

**Activity actions:**
- `createActivity(input)` — Zod per RESEARCH skeleton (id?, activityTypeId, scheduledDate `^\d{4}-\d{2}-\d{2}$`, title≥1≤200, description?≤2000, plannedDurationMin?int 1..1440, plannedDistanceKm?nonneg≤1000). Verify type belongs to user. Insert.
- `updateActivity({ id, ...patch })` — Zod patch shape; verify ownership; allow updating title/description/plannedDurationMin/plannedDistanceKm/activityTypeId.
- `moveActivity({ id, scheduledDate, dayOrderIndex? })` — drag-drop reschedule (D-03). Verify ownership; update.
- `completeActivity({ id, actualDurationMin?, actualDistanceKm? })` — set `status='done'`, `completedAt = now()`, store actuals (null allowed for "skip logging" — D-09).
- `cancelActivity({ id })` — set `status='cancelled'`.
- `skipActivity({ id })` — set `status='skipped'`.
- `deleteActivity({ id })` — hard delete (this is per-day data; archive doesn't make sense). Verify ownership.

Every action returns `ActionResult`. Every action validates input via Zod and calls `getUserId()` first. All Drizzle writes must include `userId` in the WHERE clause when targeting an existing row.

Distance values come in as numbers but Drizzle `numeric` expects string — convert via `.toString()` per RESEARCH skeleton.

No `revalidatePath()` calls — Realtime + TanStack Query handles refresh per Critical Pattern 3.

Per TRN-01, TRN-02, TRN-06, TRN-07, TRN-08; D-08, D-09, D-11.
