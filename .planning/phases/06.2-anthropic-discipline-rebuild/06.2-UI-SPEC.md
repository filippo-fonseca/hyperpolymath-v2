## §2 The Discipline-First Organizing Principle

> **The Anthropic discipline lives EVERYWHERE. JARVIS mood is the cherry on top, not the cake.**

This section is the heart. Every later decision in this UI-SPEC references back to it.

### 2a. Why Phase 6.1 was wrong about discipline scope

Phase 6.1 §2d declared a **"discipline-vs-theatrics split"**: JARVIS-mode surfaces (`/`, `/insights`, `/health`, `/settings/memory`) got HUD theatrics; document-mode surfaces (Tasks/Captures/Projects/Settings) got Notion discipline. The split made the discipline **local** — applied per surface.

That was the wrong-pole failure. The discipline is not local. It is **the floor under every surface**. Theatrics doesn't sit beside discipline — theatrics sits ON TOP of discipline, in a strictly bounded location, as a single focal moment.

### 2b. Phase 6.2 reframe

| Question | 6.1 answer | 6.2 answer |
|---|---|---|
| Where does Anthropic discipline apply? | Document surfaces only | **EVERY surface** (Console, document, agent-adjacent, modals, toasts) |
| Where does JARVIS mood appear? | Across every agent surface (4 routes + global edges + global corners + global focus rings) | **JARVIS Console only**, in TWO specific moments (composer border at focus + streaming caret) |
| What carries the brand identity? | Cumulative cyan chrome density + always-on motion | Type + whitespace + ONE perfect accent + Anthropic-grade interaction polish |
| Is the discipline conditional? | Yes (per-surface) | **No.** Discipline is non-negotiable. Mood is the conditional element, scoped tight. |

### 2c. The "would Anthropic ship this?" test (the gate every executor uses)

Every visual decision must pass:

1. **Would Anthropic ship this?** If no, revert.
2. **Is this the ONE focal moment, or am I adding density?** If the latter, cut.
3. **Would removing this element actually hurt the user's experience?** If three "no"s, cut.

The test is enforced by `gsd-ui-checker` (validation) and `gsd-ui-auditor` (post-implementation).

### 3d. Border philosophy

Per Anthropic MCP design guidelines (RESEARCH §3.3):

- **Default border thickness: 1px.** (0.5px is the Anthropic ideal but inconsistent subpixel rendering on certain monitors makes 1px the safer floor for Hyperpolymath. Half-pixel reserved as opt-in for the composer.)
- **Composer border specifically: `border-[0.5px]` opt-in** via custom utility — this is the one place we test Anthropic's hairline.
- **Border opacity: 15-25% alpha** by default. Borders are **colored-ink at low alpha**, not pure stroke. Tailwind syntax: `border-[rgb(20_37_32_/_0.20)]` (light) / `border-[rgb(255_255_255_/_0.15)]` (dark).
- **NO `box-shadow` ambient depth.** Borders carry structure; shadows do not. Single exception: the JARVIS Console composer focus state, which adds the `--hud-cyan-glow-soft` outward glow.

### 3e. Color budget (target — measured at idle, across the full app)

Match Anthropic's claude.ai ratio (RESEARCH §7.3):

| Layer | Target % | What carries it |
|---|---|---|
| Canvas + surface (background tier) | **70%** | `--canvas`, `--surface`, `--surface-raised` |
| Ink + ink-muted (content tier) | **25%** | Body text, headings, secondary text, icons |
| Accent (decoration + identity tier) | **<5%** | Cyan in TWO Console moments + intent dots app-wide |

Phase 6.1's effective budget was ~55/30/12/3 — **3-4× more accent than Anthropic.** Phase 6.2 halves it.

### 3f. Semantic colors (NOT tied to brand)

Per Anthropic restraint: no separate `success / warning / info / danger` color tracks. The three intent inks (sage / coral / amber) carry semantic load AT THE APPLICATION LAYER (not as design tokens themselves):

| Info / neutral | `--ink-muted` | `/health` `n/a` status, sonner info, deferred states |

No new tokens. No `--success`, no `--error`, no `--warning`. Anthropic-grade restraint.

## §4 Typography

### 4a. The three-role type scale (Anthropic MCP — RESEARCH §3.1)

Phase 6.1 used 4 canonical sizes + 1 declared exception. Phase 6.2 collapses to **three semantic roles** + 1 declared exception, per Anthropic's published MCP type scale.

| Role | Size | Weight | Line height | Font | Letter-spacing | Where it lives |
|---|---|---|---|---|---|---|
| **Display / Heading** | 28-36px (responsive — 28 on `< md`, 36 on `≥ md`) | EB Garamond **600** (semibold) | 1.1 | `var(--font-serif)` | **`tracking-tight`** (-0.025em) | Page H1: `/health`, `/insights`, `/captures`, `/projects/[id]`, `/settings`, `/tasks` |
| **Subhead / Section** | 20-24px (responsive — 20 on `< md`, 24 on `≥ md`) | EB Garamond **600** | 1.25 | `var(--font-serif)` | `tracking-tight` (only at 24px) | Section H2 inside pages, modal/dialog titles |
| **Body** | 16px | EB Garamond **400** | 1.5 | `var(--font-serif)` | normal | Default body text on every surface; default button label; default form input value |
| **Caption / Meta** | 12px | JetBrains Mono **400** | 1.4 | `var(--font-mono)` | `tracking-[0.04em]` (slight tracking helps mono read at 12px) | Timestamps, IDs, status values on `/health`, latency strip, receipt metadata, sidebar section labels |
| **Declared exception: console meta strip** | 11px | JetBrains Mono **400** | 1.0 | `var(--font-mono)` | `tracking-[0.06em]` | **JARVIS Console bottom-right `latency: 287ms` strip only.** This is the single 11px usage in the app. |
| **JARVIS prose (assistant turn)** | 16px | JetBrains Mono **500 italic** | **1.65rem (26.4px)** per claude.ai | `var(--font-mono)` | normal | JARVIS Console assistant message stream — full-width, no bubble (RESEARCH §3.4) |

> **Anthropic Copernicus rule (RESEARCH §3.1):** Display weights NEVER bold. EB Garamond 600 is the
> "bold" cap — no `font-bold` (700) anywhere. **`tracking-tight` on EB Garamond ≥ 24px is mandatory** —
> Anthropic's negative letter-spacing rule translates directly. EB Garamond at 24px without
> tracking-tight "reads as off-brand" (per Anthropic Copernicus prescription, RESEARCH §3.1).

### 4b. Font weights — the strict allowlist (the "two weights per surface" rule)

| Font | Allowed weights | FORBIDDEN |
|---|---|---|
| EB Garamond | **400** (regular) + **600** (semibold) | ❌ 500 (medium) — Anthropic Styrene-vs-Copernicus rule forbids mid-weight on serif; ❌ 700 (bold) — Copernicus rule "NEVER bold"; ❌ 400 italic outside literary body emphasis |
| JetBrains Mono | **400** (regular) + **500 italic** (JARVIS prose register only) | ❌ 500 upright; ❌ 600 / 700 anywhere; ❌ 400 italic outside chrome captions |

The current `next/font/google` declarations in `apps/web/app/layout.tsx` should be **tightened to ship only these subsets** (executor task — drop unused weight variants from the font loader to reduce bundle).

### 4c. Hierarchy enforcement rules

1. **Hierarchy is communicated by SIZE × WEIGHT × TRACKING — not by color.** No `text-amber-600 H2` etc. Headings are always `--ink`.
2. **No additional sizes invented.** If a surface needs an intermediate hierarchy level, use a different weight or tracking — not a new px value. The checker grep-tests this.
3. **`tracking-tight` (Tailwind = -0.025em) applies to ALL EB Garamond ≥ 24px.** Mandatory.
4. **JARVIS prose line-height = `leading-[1.65rem]`** (exact claude.ai value). The 1.65rem on 16px = 26.4px effective. Don't use Tailwind's `leading-relaxed` (1.625) — close but not exact; use the literal `[1.65rem]` for fidelity.
5. **Mono is for data-points + JARVIS prose ONLY.** Carry-forward from §3 Pitfall 5: mono on sidebar nav, mono on agent-surface H1, mono on receipt titles — all FORBIDDEN.
6. **No `font-medium` on EB Garamond.** Anywhere. Period.

### 4d. Reading-rhythm rules (Anthropic MCP line-heights)

| Type role | Line height | Source |
|---|---|---|
| Extra-large display | 1.0 | Anthropic MCP |
| Large headings (24px+) | 1.1 | Anthropic MCP |
| Mid headings (20px) | 1.25 | Anthropic MCP |
| Body | 1.5 (Hyperpolymath default; Anthropic's 1.4 reserved for tighter UI) | Anthropic MCP + Tailwind `leading-relaxed` proximity |
| JARVIS prose | 1.65rem (literal) | claude.ai exact value |
| Mono caption | 1.4 | Anthropic MCP |

## §6 Motion Vocabulary

### 6a. The collapse — from 7 states to 3, from 19 rows to 14

Phase 6.1 shipped:
- A 7-state JARVIS Console choreography machine (`idle / focused-idle / typing / submitting-ignite / thinking-radial / streaming-with-light-trail / done-scan / error-glitch`)
- A 5-easing vocabulary (`out-quart / in-out-circ / out-back / in-fast / linear`)
- A 19-row duration/easing table
- 12 `@keyframes` (corner-breathe, focus-breathe, thinking-sweep, streaming-caret-pulse, submit-ignite, submit-scan-drop, scan-reveal, receipt-outline-trace, receipt-shimmer, edge-tick, undo-wipe, error-glitch, core-rotate-slow, core-rotate-fast, core-breathe)
- ~8 always-on animations (corner crops breathe, focus ring breathing, scan ambient, receipt shimmer queued, edge tick, core rotation)

**Phase 6.2 collapses to:**

- 3 quiet states on the JARVIS Console: `idle` / `streaming` / `done`. Optional 4th: `error` (subtle text color shift, no animation)
- **1 canonical easing curve:** `--ease-out-quart` (`cubic-bezier(0.25, 1, 0.5, 1)`)
- **3 durations:** 150ms (hover, exit), 200ms (state change, modal enter), 800ms (one-shot only — `/insights` chart stroke draw-in on mount)
- **1 surviving keyframe** (sonner-managed shimmer for skeleton screens — see §6c)
- **ZERO always-on animations.** Static at idle. Motion only on user-initiated actions.

### 6b. The new motion table (Anthropic-restrained — RESEARCH §8.5)

| Animation | Duration | Easing | Reduced-motion |
|---|---|---|---|
| Page transition (template.tsx fade) | 150ms | `--ease-out-quart` | 0ms (instant) |
| Hover entrance (button, link, icon, action bar reveal) | 150ms | `--ease-out-quart` | 0ms |
| Hover exit | 150ms | `--ease-out-quart` (no separate exit curve) | 0ms |
| Focus state (border darken / ring fade-in) | 200ms | `--ease-out-quart` | static (no motion, ring appears instantly) |
| State change (idle → streaming, streaming → done) | 200ms | `--ease-out-quart` | opacity-only |
| Modal / dialog enter | 200ms | `--ease-out-quart` (opacity + scale `0.98 → 1.0`) | opacity-only |
| Modal / dialog exit | 150ms | `--ease-out-quart` (opacity-only) | 0ms |
| Toast enter / exit | sonner-managed (~250/200ms) | sonner default | sonner-reduced |
| List item enter (motion/react layout) | 220ms | `--ease-out-quart` | opacity-only |

The checker (`gsd-ui-checker`) and auditor (`gsd-ui-auditor`) grep-verify these. Each entry must be **absent** from the implemented codebase.

### 12b. Typography anti-patterns

- ❌ **Mono italic H1 on `/health`** — explicitly the 6.1 rejection. (See §14.)
- ❌ **More than 4 type roles per surface** — three semantic roles + the declared 11px exception.

### 12c. Motion anti-patterns

- ❌ **Always-on `infinite` animations** — except the skeleton-screen shimmer. Grep: `animation:.*infinite` on any selector outside `.skeleton` is flagged.
- ❌ **Breathing focus rings** — `.hud-focus-breathe` deleted; no replacement.
- ❌ **Corner-crop breathe** — deleted.

- ❌ **Error glitch** — deleted; errors use subtle coral text.
- ❌ **7-state motion machines** — 3 states only.
- ❌ **More than 1 easing curve** — `--ease-out-quart` is the canonical curve.
- ❌ **More than 3 durations** — 150ms / 200ms / 800ms (one-shot).

### 12d. Color anti-patterns

- ❌ **Cyan focus rings on document surfaces** — `--ring-doc` (amber) is the only doc-surface focus ring.
- ❌ **Intent inks as borders or full backgrounds** — dots only.

- ❌ **`--ink-coral` / `--ink-sage` / `--ink-amber` on chart series** — those are document-side intent dots only. Charts use cyan family.

### 12e. Copy anti-patterns

- ❌ "AI-powered", "magical", "intuitive", "revolutionary", "stunning", "beautiful", "seamless", "effortless" — see §11b.
- ❌ Title Case Marketing Speak — sentence case is the floor.

- ❌ "Powered by Claude" / "Powered by Anthropic" anywhere visible (license-required attribution lives in `/settings` or `/about`, not as chrome).

### 12f. Loading state anti-patterns

- ❌ **Spinners for inline content** — Anthropic explicit rule. Use skeleton screens shaped like the eventual content. (`<Loader2 />` import from Lucide should appear 0 times in non-Console loading states.)
