## Summary

This is the **third visual rebuild** of Hyperpolymath v2. Phase 6 (neumorphic + JARVIS-blue) was rejected as "I do not like the UI." Phase 6.1 (Stark HUD vocabulary translated through Linear/Vercel discipline — corner crops, hex-grid background, 7-state JARVIS Console motion machine, arc-reactor centerpiece, edge instrumentation rails, cyan everywhere on agent surfaces) was rejected with the same vocabulary: *"i still do not like how it looks and everything feels clunky and blah. research properly the UI of claude code / anthropic + notion paired with something like what jarvis from tony stark has."*

The pattern is unmistakable: the **discipline pole** was wrong both times. Material/neumorphic was wrong (Phase 6). Linear/Vercel/Stark was also wrong (Phase 6.1). The user wants **Anthropic-level interaction craftsmanship as the floor**, NOT more JARVIS theatrics. Restraint is the verb. Type + whitespace + ONE perfect accent + atmospheric depth as a *mood* must carry the brand — not literal HUD components scattered across every surface.

Cyan stays — the user reinforced it 2026-05-19 PM via a second image reference: *"for the accent color, remember... we are doing it jarvis-esque like in the tony stark movie."* The problem was never the color. The problem was **cumulative application**: cyan everywhere on agent surfaces + supporting HUD chrome on every viewport made the surface feel "clunky and blah." Phase 6.2 keeps cyan as the signature accent but applies it like Anthropic applies their orange `#c96442` — sparingly, perfectly placed, never as ambient decoration.

**Primary recommendation:** Re-anchor every surface to **Anthropic's published design discipline** (verified via their MCP app design guidelines): three-level type scale, two weights, generous padding + logical groupings, host-token semantic colors, skeleton screens (no spinners), corner radii 4–12px + full, **brand accent for IDENTITY only — host tokens carry structure**. Apply that floor everywhere. Then, on the JARVIS Console only, allow ONE focal moment that carries the cyan + soft glow + atmospheric depth — the mood reference. Cut HudCoreBubble, HudCornerCrops-on-every-surface, hex-grid layered background, 7-state motion machine, edge instrumentation rails, and the always-on motion (breathing focus / corner-crop breathe / scan ambient). Collapse the 7-state motion machine to 3 quiet states (idle / streaming / done).

The data:

| Phase | Discipline pole tried | Visual contract shipped | User reaction | Verbatim |
|---|---|---|---|---|
| Phase 6 | Material / neumorphic | Soft-shadow neumorphic cards + JARVIS-blue `#00d4ff` accent palette | Rejected | *"I do not like the UI. Needs to look like as if the UI for JARVIS from Tony Stark had a baby with Notion."* |

The diagnosis:

- **The failure mode is not "wrong reference image."** Phase 6.1 implemented the Stark vocabulary correctly per its UI-SPEC. The CUMULATIVE effect was the failure — too much chrome, too many simultaneous animations, too much visual density.

The signal is dial DOWN ambient chrome, ANIMATE LESS but PERFECTLY, let TYPOGRAPHY + WHITESPACE + ONE PERFECT ACCENT carry the brand.

The reframe:

> **Anthropic + Notion + Claude Code are the PRIMARY discipline; JARVIS is the ATMOSPHERIC backing vocal, not the lead instrument.**

Two visual contracts in a row pushed HARD on JARVIS and treated Notion as a secondary discipline. The right ratio inverts that.

## §3 Anthropic Deep-Dive — claude.ai + claude.com + console.anthropic.com

The most important single section of this research. Multiple sources cross-verified (HIGH confidence).

### §3.1 The Anthropic typography system — Copernicus + Styrene + Tiempos

| Font | Source | Role at Anthropic | Notes |
|---|---|---|---|
| **Galaxie Copernicus** (Book weight 400) | Chester Jenkins + Kris Sowersby, 2009; Village Constellation | Large headers + display sizes on claude.ai + anthropic.com | Transitional serif. **Display weight is 400 (Book) only — NEVER bold.** Negative letter-spacing `-0.3 to -1.5px` is essential per Anthropic design docs — Copernicus without it reads off-brand. Six weights exist (book/medium/semibold/bold/extrabold/heavy) but Anthropic uses ONE (Book/400) for display. |
| **Styrene B** (Regular 400 / Medium 500 / Bold 700, plus italics) | Commercial Type, Berton Hasebe + Panos Haratzopoulos + Ilya Ruderman | Chat interface body + UI labels | Sans-serif. Anthropic uses **Styrene B** specifically (the narrower, more succinct variant — the wider Styrene A is rejected for body density). "Rounded, slightly squishy" character. The font that gives claude.ai its UI personality. |
| **Tiempos Text** | Klim Type Foundry | Body running text (long-form prose, articles, marketing pages) | Transitional serif. Pairs with Copernicus headers. Used for editorial body copy on anthropic.com news posts + claude.com marketing. |
| **`ui-monospace, monospace`** | System | Code blocks + monospace data | Per Anthropic MCP guidelines: monospace fallback is `ui-monospace, monospace` — NOT a custom font. This is direction-correct: monospace is system-native. |

**The typographic personality** (per type.today + Dear Designer + Anthropic's own MCP design docs):

- Anthropic's typography intentionally **humanizes AI**: rounded Styrene B + transitional serifs (Copernicus, Tiempos) signal "warm, considered, literary" — not "tech-cold."
- The serif character is what gives Anthropic its **literary, considered voice**; switching to sans-serif display would make Claude feel like every other AI tool.
- Styrene B has "gentle, rounded quality" — words treated like "tiny pearls strung together" (Dear Designer).

**Anthropic's published MCP type scale** (HIGH confidence — verified from Anthropic's own design guidelines at claude.com/docs):

| Property | Value |
|---|---|
| Scale | **Three levels: heading, body, caption** (NO H1/H2/H3/H4/H5/H6 ladder — three roles) |
| Weights | **Two: regular (400), emphasized (500/600/700 contextually)** |
| Text sizes | **12px–20px** range for body/caption |
| Heading sizes | **12px–36px** range |
| Line heights | **1.4 body / 1.25 large text / 1.1 large headings / 1.0 extra-large** |
| Font weights available | 400 (normal) / 500 (medium) / 600 (semibold) / 700 (bold) — but only TWO used per surface |

**Translation for Hyperpolymath (EB Garamond + JetBrains Mono, NOT Copernicus + Styrene B + Tiempos — we don't have those licenses):**

- **EB Garamond 400 = Copernicus Book substitute** for display + headings. Already loaded. Use ONLY 400 + 600 (carries forward). The 6.1 rule "no font-medium for EB Garamond" stands.
- **EB Garamond 400 italic = Tiempos Text substitute** for body running prose where literary voice is wanted.
- **JetBrains Mono 400 + 500 italic** stays for the JARVIS prose register + data + chrome labels.
- **Negative letter-spacing on display headings** is the new rule worth stealing — Anthropic's `-0.3 to -1.5px` on Copernicus translates to `tracking-tight` on EB Garamond 36px H1. **This is a specific, implementable change.**

**Critical observations on color APPLICATION (the most important learning):**

1. **The orange is used SPARINGLY.** It appears on: primary CTA buttons ("Try Claude", "Send"), the claude.ai logo, key links, the streaming-response avatar. It does NOT appear on every focus ring, every border, every active state. **This is the discipline pole.** Phase 6 + 6.1's failure mode was cyan-everywhere; Anthropic's success mode is orange-sparingly.
2. **Borders carry structure, not shadows.** The composer is `rounded-2xl border #E5E0D6` with **NO shadow** — relies on border definition only. This is Anthropic's "signature flat surface" (assistant-ui). **Steal:** no neumorphic depth, no glass refraction, just clean borders.
3. **Border opacity for layering:** Anthropic's MCP docs specify "borders use opacity-based darkening (15–40%)" — meaning even the structural borders are quiet. Translation: `rgb(ink / 0.15)` not pure ink stroke.
4. **Two grays + ink + orange = the whole palette.** Anthropic doesn't have a "danger" + "success" + "info" + "warning" + multiple intents palette spam. They have: cream/white, light gray, mid gray, dark brown/ink, and orange. Status colors are added per-context as muted variants of the base.

### §3.3 Spacing + layout principles (verified from Anthropic's MCP docs)

**Anthropic's published spacing principles:**

| Principle | Specification |
|---|---|
| **Padding** | "Maintain generous padding and logical groupings. Balance information density with readability." (no specific values prescribed — emphasis on RHYTHM not RULES) |
| **Minimum viewport** | 320px; full-width layouts (no fixed margins wasting space) |
| **Max inline height** | 500px; no nested scrolling |
| **Container queries** | Use container queries; avoid fixed widths |
| **Touch target minimum** | 44×44pt |
| **Corner radii** | **4px–12px** plus full (9999px) |
| **Border thickness** | **0.5px** (yes, half-pixel — relies on subpixel rendering for the "delicate hairline" feel) |

**Layout observation from Dear Designer + assistant-ui:**

- Chat composer field on claude.ai is **"perhaps 300px tall — just enough space to write but not to overwhelm nor intimidate."**
- Composer uses `rounded-2xl` (16px radius — at the top of Anthropic's 4–12px range, actually slightly over — likely the "full" treatment for the conversational element).
- Composer padding: `px-3.5 pt-3 pb-2.5` (14px horizontal, 12px top, 10px bottom — non-symmetric vertical to account for action bar).
- Action bar uses **hover-reveal** opacity (`opacity-0 transition-opacity group-hover/message:opacity-100`) — actions appear only when hovering a message. **This is Anthropic's "calm at idle" pattern.**

**Translation:**

- Phase 6.1 used `--edge` and `--edge-hud` as 1px borders. Phase 6.2 should test 0.5px borders (Tailwind requires explicit `border-[0.5px]` or custom utility — feasible in Tailwind 4). Cleaner hairlines = more premium feel.
- Corner radii currently mix 4–24px in 6.1. Anthropic ships 4–12px on most components + full on the composer. **Standardize Hyperpolymath on: 4px (chips), 8px (cards, buttons, dialogs), 12px (inputs), 16px+ (rounded-2xl) on JARVIS Console input only.**
- **Hover-reveal action icons** (Anthropic + Notion both use this) — Phase 6.2 should adopt this pattern for all destructive/secondary actions (delete, edit, copy) on Tasks/Captures/Projects rows.

### §3.4 The claude.ai chat surface — message rendering

**User messages:** Right-aligned, `rounded-2xl bg-[#E5E0D6] max-w-[80%]` bubble. Inside the cream background, the user bubble reads as a slightly-darker tile — visual containment via tone shift, not via shadow.

**Assistant messages:** **Full-width, serif typography (Tiempos / Copernicus), NO bubble, NO avatar.** Text renders directly on the cream background with `leading-[1.65rem]` (26.4px line-height) for reading rhythm.

**Why this matters for JARVIS Console:**

> **The assistant turn DOES NOT need a bubble or card.** Phase 6.1 wrapped JARVIS prose in a bordered card with corner crops. Anthropic doesn't do that. The assistant message just IS — prose on canvas, no chrome.

**Composer (the input field):**

- `rounded-2xl` corners (16px) — only the composer gets this generous a radius
- `border #E5E0D6` — flat, no shadow
- `bg-white` (or `#1f1e1b` dark)
- `px-3.5 pt-3 pb-2.5` padding
- Action buttons (attach, model picker) inside the composer, bottom row
- Send button is **Claude orange** (`#c96442`) — the orange CTA
- Focus state: subtle — likely border darken or ring at very low opacity (specifics not extracted from CSS but inferred from "ferociously simple" Dear Designer characterization)

### §3.5 Interaction polish — Anthropic's invisible-by-design pattern

Multiple sources converge on the same observation:

- **"Ferociously simple and clear"** (Dear Designer)
- **"Friendliness through simplicity of styling that incentivizes conversation"** (Dear Designer)
- **"Functional pragmatism over emotional appeal"** (Anthropic's own design language — Claude Design announcement)
- **"Calm at idle, hover-reveal for secondary actions"** (assistant-ui Claude clone)

Anthropic's published MCP UX principles (HIGH confidence — their own docs):

| Principle | Description | Hyperpolymath implication |
|---|---|---|
| **Conversational** | "Fit naturally into dialogue. Don't force users to learn new interaction patterns." | JARVIS Console should feel like chat, not like a control panel. The 7-state motion machine forced a learn-the-states moment. Cut it. |
| **Contextual** | "Use conversation history to inform display and timing." | Existing — JARVIS already does this via session memory. No change needed. |
| **Integrated** | "Inherit styling from the environment." | Cyan only inside `.agent-mode-scope`; intent inks only on document surfaces. Carry forward from 6.1. |
| **Adaptive** | "Handle variable sizing, mobile viewports, accessibility gracefully." | AES-07 already covers this; verify in walkthrough. |
| **Progressive disclosure** | "Reveal complexity only when users need it." | Hover-reveal action icons, slash-command popover, contextual menus. Adopt for Tasks/Captures rows. |
| **Skeleton screens, NOT spinners** | "Show skeleton screens while content loads. Avoid spinners for inline content—skeletons feel more native." | **CRITICAL.** Phase 6.1's HudThinkingRing (radial sweep during model latency) is a SPINNER. Anthropic's principle says don't ship that. Recommendation: use a content-shaped skeleton during the "thinking" wait — or accept the spinner as one of the very few sanctioned exceptions specifically for JARVIS Console latency masking (the only surface where a spinner is appropriate). |

**What Anthropic explicitly rejects (their own docs):**

- Hidden menus conflicting with host container
- Deep drill-in navigation
- Chat inputs inside the app
- Fixed layouts that ignore mobile constraints
- **Hardcoded colors (must use tokens)**
- **Spinners for loading (use skeletons instead)**
- Floating panels in fullscreen mode

The hardcoded-colors-forbidden rule is structural advice — Hyperpolymath's `@theme` tokenization already satisfies it. **The spinners-forbidden rule is a direct critique of Phase 6.1's HudThinkingRing.**

### §3.6 Motion / animation — the Anthropic-restrained vocabulary

Anthropic's MCP docs are sparse on motion specifics (deliberately — they don't prescribe easing curves or durations). What they DO say:

- **"Inline cards expand to fullscreen with a smooth transition. Provide a clear visual affordance for expansion (fullscreen button or tap-to-expand). Fullscreen close returns to the conversation at the same scroll position."** — motion is for spatial continuity, not decoration.
- **"Show skeleton screens while content loads."** — no spinners for inline content.
- **"No explicit velocity, easing curves, or duration specs."** — Anthropic does NOT publish a motion language. The motion language is *restraint by default*.

**What can be inferred from claude.ai's actual behavior** (from designer reviews + chat-app clones):

| Surface | Motion observed | Implementation hint |
|---|---|---|
| Chat composer focus | Subtle border darken; possibly very-low-opacity ring | 150ms ease-out |
| Send button hover | Slight darken or opacity shift | 150ms ease-out |
| Streaming response | Tokens stream in with character cursor — minimal flourish | Just text appearing; no caret light-trail, no scan reveal on done |
| Action bar reveal | Opacity 0 → 1 on hover | 150-200ms ease-out |
| Page navigation | Standard browser routing; no custom page transitions on claude.ai | n/a — but Phase 6.1 already shipped template.tsx page transition; keep as ONE quiet 150ms opacity-only fade |

**The general principle from research:**

- **Micro-interactions: 150-250ms durations.** Anything faster feels instant. Anything slower feels sluggish.
- **Default to ease-out for entrances** (`cubic-bezier(0.25, 1, 0.5, 1)` — `--ease-out-quart` already in 6.1's substrate).
- **Hover responses: instant on, ease-out off (150ms).** Don't ease-in hovers — feels slow.
- **NO always-on motion.** No breathing focus rings. No corner-crop breathe. No scan ambient. No persistent shimmer.

**Translation for Phase 6.2:**

- Collapse 6.1's 7-state JARVIS Console motion machine to **3 quiet states**: `idle / streaming / done`. The `submit-ignite` overshoot moment, `thinking-radial` sweep, `error-glitch`, `focused-idle breathe`, and `typing` dot all GO.
- Keep `--ease-out-quart` as the single canonical curve (Anthropic ships restraint, not a curve library).
- Keep template.tsx page transition (150ms opacity fade — already shipped per 6.1-06).
- Keep `useReducedMotion()` guards from 6.1 — direction-independent.

## §11 Common Pitfalls

### Pitfall 1: Treating cyan as a "feature" instead of an "accent"
**What goes wrong:** Designer applies cyan to every focus ring, every chart stroke, every status pill, every active-state border — creating cumulative cyan density.
**Why it happens:** Cyan is the "JARVIS signature." Designer thinks more = more JARVIS-feeling. Wrong — Anthropic's lesson is the opposite. Less = more.
**How to avoid:** **The "Anthropic orange test."** Anthropic applies orange in <5% of pixels. Apply cyan in <5% of pixels too. If a surface has multiple cyan elements, cut all but one.
**Warning signs:** UI feels "busy" or "instrument-paneled" at rest. Multiple cyan elements visible without user interaction. Designer is reaching for cyan as a default accent.

### Pitfall 2: Confusing "atmospheric mood" with "visual vocabulary"
**What goes wrong:** Designer sees the Stark HUD reference and ships literal HUD components (arc reactor, radial dials, corner crops, hex grid, edge instrumentation rails).
**Why it happens:** The user shared the image. Designer interprets the image as "draw this." Wrong — the image is a MOOD reference, not a layout target.
**How to avoid:** Every HUD-shaped element must pass three tests: (a) would Anthropic ship this? (b) is this the ONE focal moment, or am I adding density? (c) would removing this element actually hurt the user's experience? If three "no"s, cut.
**Warning signs:** UI-SPEC has multiple components named `Hud*`. UI-SPEC declares motion choreography with 5+ states. UI-SPEC has any element described as "always-on" or "ambient."

### Pitfall 3: Adding spinners instead of skeleton screens
**What goes wrong:** Designer ships HudThinkingRing-style spinners for loading states across Tasks/Captures/Calendar.
**Why it happens:** Spinners are the React/Next default; Designer doesn't think about loading state explicitly.
**How to avoid:** Anthropic's explicit MCP rule: "Skeleton screens, NOT spinners. Match the layout structure of the final content." Apply to every loading state. The single exception is the JARVIS Console thinking-word indicator (canonical agent-working pattern from Claude Code).
**Warning signs:** Any `<Spinner />` or `<Loader2 />` component in the loading state of a list view.

### Pitfall 4: Always-on motion creeping back in
**What goes wrong:** Designer adds "subtle" breathing/scan/shimmer/glow ambient because "the surface feels static otherwise."
**Why it happens:** Designer reflex — "alive" UI must move. Wrong — Anthropic ships completely static surfaces. Motion appears on user interaction, not at rest.
**How to avoid:** UI-SPEC must include the rule: **NO always-on motion. Motion only on user-initiated actions.** Reduced-motion guards are belt-and-suspenders for the same reason.
**Warning signs:** UI-SPEC mentions "breathe," "ambient," "shimmer," "pulse" loops, "drift," "scan ambient." Any `@keyframes` with an infinite loop on an idle element.

### Pitfall 5: Reverting to mono-everywhere on agent surfaces
**What goes wrong:** Designer ships JetBrains Mono on every label, header, button, section title in `.agent-mode-scope`.
**Why it happens:** Phase 6.1 declared "mono = machine speaking, serif = you writing" and the designer extends the rule too broadly.
**How to avoid:** Mono is for: data points (timestamps, IDs, latency, status values), JARVIS prose register, the ⌘K hint chip, the ONE bottom meta strip on the Console. Everything else — including agent-surface H1, section labels, button labels — uses EB Garamond.
**Warning signs:** /insights H1 in mono. /health page heading in mono italic. Sidebar nav links in mono uppercase. Receipt title in mono.

### Pitfall 6: Border weight inflation
**What goes wrong:** Designer uses `border-2` or `border-[2px]` because "borders aren't visible enough."
**Why it happens:** Tailwind default border is 1px and at low alpha can disappear on certain monitors.
**How to avoid:** Per Anthropic MCP: 0.5px borders. Per Anthropic actual: 1px borders at 15-25% alpha. Both feel premium. `border-2` reads as "Material design."
**Warning signs:** Any `border-2` or thicker on a structural element.

### Pitfall 7: Designing for the rejection memory instead of for Anthropic
**What goes wrong:** Designer over-corrects from Phase 6.1's HUD-heavy direction and ships a UI that's TOO sparse — drops the thinking-word indicator, cuts the streaming caret cyan, removes intent dots from receipts. The result is bland.
**Why it happens:** Designer hears "user wants restraint" and removes things the user actually liked.
**How to avoid:** The user liked: streaming UX, intent dots on receipts, dark mode, generous typography, cyan as a color choice. Don't remove those. The user rejected: the cumulative ambient chrome density.
**Warning signs:** UI-SPEC removes elements that aren't on the explicit Phase 6.2 revert list (§9).

## §14 Open Questions

1. **Light mode treatment depth vs Anthropic's actual claude.ai light mode.**
   - What we know: claude.ai light uses `#F0ECE0` bg + `#E5E0D6` composer border + `#c96442` orange — restrained, content-first.
   - What's unclear: Hyperpolymath's existing light mode uses `#f5f3ec` parchment per Phase 6.1 — close enough to Anthropic's `#F0ECE0` to call it the same family? Or tune Hyperpolymath warmer to differentiate?
   - Recommendation: Keep Phase 6.1's OKLCH base palette (`oklch(97% 0.005 75)` ≈ `#f5f3ec`). The slight warmth differentiates from Anthropic while keeping the same family. UI-SPEC author confirms or tunes.

   - What we know: 6.1's `.agent-mode-scope` was used to scope cyan focus rings + always-on HUD chrome to specific routes.
   - What's unclear: After §9's revert list strips HUD chrome from every surface except the JARVIS Console, is `.agent-mode-scope` still needed? Or just apply the cyan focus rules to the Console composer directly?
   - Recommendation: Keep the class as a mechanism (cheap to retain). Restrict its usage to the JARVIS Console route. Drop it from `/insights`, `/health`, `/settings/memory`.

3. **The cyan stroke on `/insights` charts — is it Anthropic-discipline-violating?**
   - What we know: Anthropic uses orange on charts on anthropic.com (rare, but yes — for data series). Following the principle, cyan on Hyperpolymath chart series is acceptable.
   - What's unclear: Should `/insights` use cyan for ALL chart series, or mix cyan + intent inks (amber for tasks distribution, sage for captures, etc.)?
   - Recommendation: Use cyan as the primary series color (signal: "agent telemetry"). Where multi-series is needed (action-type distribution stacked bar), use cyan + a desaturated secondary (cyan-dim) + tertiary (cyan-darker). NO amber/sage/coral on charts — those are doc-side intent dots only.

4. **The status pill on JARVIS Console — keep or cut?**
   - What we know: Phase 6.1 ships HudStatusPill in the top-right of the Console with READY / STREAMING / THINKING / ERROR states.
   - What's unclear: Is the status pill an Anthropic-discipline violation (HUD chrome) or a calm sanctioned indicator?
   - Recommendation: Cut the status pill. Claude Code doesn't have one in its CLI; the assistant turn rendering speaks for itself ("streaming" = caret active; "done" = caret gone; "error" = subtle coral text). The pill was Phase 6.1 over-coding.

5. **The Cmd+K hint chip on the JARVIS Console — keep or cut?**
   - What we know: Phase 6.1 ships a `⌘K` chip trailing-right inside the composer (per UI-SPEC §9e).
   - What's unclear: Does Anthropic show keyboard shortcuts inline in the composer (claude.ai does NOT do this — keyboard shortcuts live in a help modal)?
   - Recommendation: Keep the `⌘K` chip — it's a Hyperpolymath-specific affordance (focus the JARVIS input from anywhere in the app, AES-05). It's a small mono caption inside the composer — passes the "would Anthropic ship this" test as an information indicator, not as chrome decoration.

6. **The thinking-word indicator on JARVIS Console — keep or replace with Claude Code's 5-glyph cycle?**
   - What we know: Phase 5 shipped an animated thinking-word indicator. Claude Code uses a 5-Unicode-glyph cycle (`· ✢ ✳ ✶ ✽`) + 184+ verb list.
   - What's unclear: Should Hyperpolymath adopt Claude Code's exact spinner UX?
   - Recommendation: Keep Hyperpolymath's existing thinking-word — already in the same DNA. Don't add the glyph cycle — feature creep. The verb-cycle pattern is Anthropic-direction-correct as currently shipped.

7. **Brand voice synthesis tone — when does Genz-Renaissance over-shadow Anthropic-trustworthy?**
   - What we know: AES-04 shipped in 06.1-05; brand voice is "confident, literate, unapologetic." Anthropic's voice is "warm, trustworthy, restrained."
   - What's unclear: At what point does "confident" read as "salesy" against Anthropic's "warm"?
   - Recommendation: Run the final tone alignment pass on receipts, empty states, error messages, and toast copy. Tighten anywhere copy reads "marketing" (any superlatives, any over-promising). Keep the literary edge — that's the Renaissance pole and it pairs well with Anthropic's literary type system.
