## Surface Contracts

This phase introduces and restyles the following surfaces. Each specifies the exact CSS class composition.

### S-1: Inbox Surface (always-present panel)

**Current state:** Collapsed tray, toggle via `KanbanDayHeader` pill, 24-card truncation.
**New state:** Persistent, always-visible panel. Remove collapse toggle and truncation.

```
Layout: fixed-width side column OR top-spanning lane (see S-1 layout note below)
Class: glass-tile rounded-xl p-4
Drag-target active class: [--glass-glow-color:var(--hud-cyan)] [--glass-border:color-mix(in_oklch,var(--hud-cyan)_50%,transparent)] ring-1 ring-[var(--hud-cyan)]/30
Section label: font-mono text-[11px] uppercase tracking-[0.18em] text-[var(--ink-muted)]
Count badge: font-mono text-[11px] tabular-nums text-[var(--ink-muted)]
```

**Primary visual anchor:** The persistent Inbox side-column is the strongest new focal element introduced in this phase. Its fixed presence at the left edge of the tasks surface anchors the page composition and makes the "parking lot" mental model immediately legible without any toggle interaction.

**S-1 Layout recommendation (Claude's Discretion):**
Render Inbox as a **persistent left-side column** sitting alongside the kanban columns in `TasksClient`'s flex-row layout. Width: 240px fixed, flex-shrink-0. This reads as a natural "parking lot" to the left of the day-scoped work surface, matching the mental model of "everything dateless lives here." Alternative: a horizontal lane above the kanban columns (current tray approach, promoted). The side-column approach is recommended as it makes the Inbox always legible without consuming vertical real estate.

### S-2: Day Switcher (universal / global)

**Current state:** Lives only in `KanbanDayHeader`, only shown in kanban view.
**New state:** Promoted to `TasksClient` level, rendered above the view toggle toolbar, visible in kanban / list / overview views alike.

```
Container: flex items-center gap-2 px-1 pb-3
Arrow buttons: Button variant="ghost" size="sm" h-7 w-7 p-0 aria-label="Previous day" / aria-label="Next day" — existing pattern preserved
"Today" button: font-mono text-[11px] uppercase tracking-[0.06em] h-7 px-2 — existing
Date label: font-serif text-base text-[var(--ink)] — clickable, opens native date picker
Picker trigger: same hidden <input type="date"> technique as KanbanDayHeader
```

The day switcher replaces the per-view day header. The existing `KanbanDayHeader` component is refactored or split: day navigation logic lifts to `TasksClient`, the Inbox toggle moves to the Inbox surface itself (no longer in the day header since Inbox is always visible).

### S-3: Detail Panel (glassy restyle)

**Current state:** shadcn `Sheet` with plain white/surface background, heavy border-b header.
**New state:** Sheet retains side-panel mechanism; interior surfaces apply `glass-tile` language.

```
Sheet width: 420px (preserved)
SheetContent class: add "glass-tile" or equivalent manual token application
  (SheetContent is a Radix overlay — backdrop-filter applies to the panel interior,
   not blurring behind the sheet; this is intentional: glass feel inside the panel)
Panel background: var(--glass-bg) with backdrop-filter: blur(12px) on the panel container
Header: px-6 pt-6 pb-4 border-b border-[var(--glass-border)] (replaces hard --edge border)
Title input: font-serif text-xl font-semibold — preserved; bottom border uses --edge-hud on focus
Field labels (FieldSection): font-mono text-[11px] uppercase tracking-[0.18em] text-[var(--ink-muted)]
Field rows: py-2 gap-2 — preserved
Save button: glass-button rounded-md px-4 py-1.5 font-mono text-[11px] uppercase tracking-[0.06em]
Cancel / Delete: ghost treatment — text-[var(--ink-muted)] hover:text-[var(--ink-coral)]
```

**Due-date field inline clear affordance (new — Decision 3):**

```
Container: flex items-center gap-2
Date input: existing <Input type="date"> or text display
Clear button: appears only when dueDate is non-empty; inline after the date value
  Icon: X size={12} strokeWidth={1.5} from lucide-react
  Style: text-[var(--ink-muted)] hover:text-[var(--ink-coral)] cursor-pointer-always p-0.5 rounded
  Tooltip: "Clear due date (move to Inbox)"
  Action: set("dueDate", "") → on save, maps to null (existing null-save path)
```

This clear button replaces the need to navigate the MoveToMenu for this operation. The `MoveToMenu` "Clear due date" item is kept as a secondary path but the inline affordance is the primary.

### S-4: Kanban Cards (glassy restyle)

**Current state:** TaskCard uses `var(--surface-raised)` background with a thin border.
**New state:** Apply `glass-tile` at the card tier (the per-callsite accent override pattern allows column-color rim per card via `[--glass-glow-color:...]`).

```
Base class: glass-tile rounded-lg px-3 py-2.5
Hover: inherits glass-tile:hover (cyan border tint + deepened glow) — existing
Dragging state: opacity-50 scale-95 — existing DnD pattern preserved
Selected state: [--glass-glow-color:var(--ink-amber)] ring-1 ring-[var(--ink-amber)]/40
```

Note: The `border-radius` is `rounded-lg` (8px) for cards, `rounded-xl` (12px) for panels and the Inbox surface — consistent with the existing callsite convention documented in globals.css.

### S-5: List View (day-scoped)

**Current state:** Date-agnostic, shows all tasks.
**New state:** Filters to tasks where `dueDate === dateYmd` (same YMD string comparison as kanban). Inbox tasks are excluded from the list body and shown in S-1.

No new visual surface — list items reuse `TaskCard` (which gets the glassy restyle from S-4).

### S-6: Overview / Home View (new fourth view mode)

**Implementation recommendation (Claude's Discretion):** Add `"overview"` as a fourth `view` value in the nuqs `view` param. The overview renders a vertical stack of day-group toggle rows — one per day, covering today + next 6 days by default.

```
Day group row (closed): 
  Class: flex items-center justify-between px-4 py-2.5 rounded-lg cursor-pointer-always
         border border-[var(--edge)] hover:border-[var(--edge-hud)] transition-colors duration-150
  Day label: font-serif text-base text-[var(--ink)]
  Task count badge: font-mono text-[11px] text-[var(--ink-muted)] tabular-nums
  Toggle chevron: ChevronDown/ChevronRight size={14} text-[var(--ink-muted)]

Day group body (open / expanded):
  Class: glass-tile rounded-xl p-3 mt-1 mb-2 space-y-1
  Contains: flat list of TaskCards (S-4 glassy style, compact variant)
```

The overview is NOT a new layout system — it wraps existing TaskCard in a collapsible day-group container. The selected `dateYmd` should sync: clicking a day row's header sets the universal day state and switches to kanban view (so the user drills in).

### S-7: Expand / Fullscreen Toggle

**Implementation recommendation (Claude's Discretion):** Add an expand toggle to the page header area (top-right, near the page title). Clicking it applies a CSS class to the tasks root element that hides the app sidebar (e.g., sets a `data-expanded` attribute that the sidebar layout reads via a CSS selector or a React context flag).

```
Toggle button position: top-right of the tasks page header row (flex row with h1 and stats)
Icon: Maximize2 / Minimize2 from lucide-react, size={16} strokeWidth={1.5}
Style: text-[var(--ink-muted)] hover:text-[var(--ink)] p-1 rounded cursor-pointer-always
       transition-colors duration-150 ease-out
Expanded state: sidebar hidden via CSS (e.g. parent layout reads data-expanded on main)
URL state: no — fullscreen is ephemeral UI preference, localStorage key "tasks-expanded"
```

### S-8: Completed (lesno) Day Section

**Current state:** Hidden globally unless `showLesno=true`.
**New state:** In kanban and list views, when a day is selected, completed tasks for that day appear in a collapsible "Done" section below the active columns. The global `showLesno` toggle remains for non-day-scoped contexts (e.g., the overview day groups).

```
"Done" section label: font-mono text-[11px] uppercase tracking-[0.18em] text-[var(--ink-muted)] "· done"
Section container: mt-4 space-y-1 border-t border-[var(--edge)] pt-3
Lesno cards: TaskCard with opacity-70 and a strikethrough on the title text
  Title style: line-through text-[var(--ink-muted)]
```

Day-scoped lesno visibility check: `t.status === "lesno" && t.dueDate === dateYmd` (or `completedAt` local date matches dateYmd — planner to decide; both are viable, prefer `dueDate` for consistency with the existing YMD comparison pattern).

## Interaction Contracts

### I-1: Drag Card to Inbox

**Trigger:** User drags a kanban card and releases it over the Inbox surface (S-1).
**Visual during drag:** Inbox surface applies the active drag-target ring (`--hud-cyan` glow, S-1 active class).
**On drop:** Call `bulkUpdateTaskDueDate({ ids: [id], dueDate: null })` server action. Optimistic update: remove from `dayFilteredTasks`, add to `inboxTasks`. No toast (silent, immediate).
**Revert:** On server error, `toast.error("Couldn't move to Inbox. Try again.")`.

### I-2: Clear Due Date (panel inline)

**Trigger:** User clicks the X clear button on the due-date field in the detail panel.
**Action:** `set("dueDate", "")` → on Save, existing null-save path sends `dueDate: null` to `updateTask`.
**Visual feedback:** The date input empties; a subtle `font-mono text-[11px] text-[var(--ink-muted)]` label "Will move to Inbox" appears below the field.
**No confirm dialog** — this is a reversible action (user can re-assign a date immediately).

### I-3: Day Switch (universal)

**Trigger:** Prev/next arrow, "Today" button, or native date picker.
**Effect:** Updates `dateYmd` URL param via nuqs. All views (kanban, list, overview) re-filter synchronously since they all read from the same `dateYmd`. No loading state shown.
**Constraint:** YMD string comparison preserved; no Date object round-trips.

### I-4: Inbox Drag Source → Kanban Column

**Trigger:** User drags a card out of the Inbox surface onto a kanban column.
**Action:** Sets `dueDate = dateYmd` + `status = targetStatus` (existing `handleKanbanDrop` path, already implemented). No change needed.

### I-5: View Mode Toggle (adds "overview")

**Trigger:** View toggle pill now shows `kanban | list | overview` (replaces `kanban | list | day`).
**Note:** The existing "day" view (`TaskDayView.tsx`) may be merged into the overview, or kept hidden. Recommendation: retire "day" as a separate toggle; the day-scoped kanban already handles day-level work; overview replaces the day view role. Planner decides.

### I-6: Expand Toggle

**Trigger:** Maximize2 button click.
**Action:** Toggles `localStorage["tasks-expanded"]` + triggers sidebar collapse via state/context.
**Transition:** Sidebar width animates from its current width to 0 using Motion `layout` on the sidebar container (200ms `--ease-out-quart`). Page content expands to fill.

### I-7: JARVIS "added to inbox" receipt copy

**When:** JARVIS creates a task with no due date (the new undated path).
**Receipt copy:** `"Added to your Inbox."` (not "Added to tasks for today").
**Tool voice_summary:** `"Added '{title}' to your Inbox."` — planner verifies this in `create-task.ts`.

## Aesthetic Guardrails (load-bearing)

These are non-negotiable constraints carried from the project memory. The checker and executor must verify against these.

1. **Not neumorphic.** The `glass-tile` system uses outer raise + drop shadows with specular top edges — it is NOT the symmetric-shadow neumorphic style that was rejected. The distinction: neumorphic has no backdrop-filter, no inset glow, and uses matched shadow pairs; `glass-tile` is translucent + blurred + single-direction specular. Do not drift toward paired outer shadows.
2. **Not HUD-heavy.** Cyan appears only in the reserved-for list above. Cards, columns, and day headers do NOT get cyan borders or glow by default — only on active drag-target state and focus rings.
3. **Restraint over flash.** One motion per interaction. No staggered card entry animations, no scan-line effects on the tasks page, no corner-crop decorations. JARVIS keyframes (`hud-corner-crop`, `hud-scan-line`, etc.) are scoped to the JARVIS console; do not apply them to the tasks surface.
4. **Notion document discipline.** The tasks page is a work surface. Information density is prioritized over visual decoration. `glass-tile` on cards provides depth cues without noise.
5. **YMD string comparison preserved.** No `Date` object round-trips for day filtering. The existing `t.dueDate === dateYmd` pattern avoids UTC midnight drift.
