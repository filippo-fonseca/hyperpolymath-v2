<objective>
Flip the JARVIS default-due policy so a task created with no date lands in the Inbox (NULL), not silently dated to today, and make the receipt say so. This is the load-bearing decision D-02: "no date" must reach the Inbox every time. Touches only the two JARVIS files, so it runs in Wave 1 parallel with the glass-restyle plan.

Purpose: Today the executor dates every undated task to today, so "no date" never reaches the Inbox — defeating the whole first-class Inbox model. Reversing it is the agent-side half of the redesign.

Output: `executor.ts` routes undated tasks to `dueDate: null` and emits an inbox-aware receipt; `create-task.ts` tool description explicitly instructs the model to omit `due` for dateless requests.
</objective>
