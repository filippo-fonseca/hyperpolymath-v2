<objective>
Promote the hidden, collapsed Inbox tray into a first-class, always-present left side column and wire it as a drag drop-target that nulls a task's due date. Three locked decisions: D-01 (first-class Inbox, remove the 24-card truncation), D-04 (drag-to-Inbox nulls the date, bidirectional with the existing drag-out flow), and the Inbox toggle removal from the day header.

Purpose: "No date" must MEAN Inbox — a visible parking lot, not a hidden tray. The user can drag anything dateless here and it lands immediately.

Output: New `InboxColumn` component (glass panel + drop target), the Inbox pill removed from `KanbanDayHeader`, and `TasksClient` rendering the Inbox persistently with a `handleInboxDrop` handler reusing `bulkUpdateTaskDueDate`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → server action `bulkUpdateTaskDueDate` | Existing, already-authenticated boundary. The drop handler sends task IDs (UUIDs the client already holds from the RLS-scoped query) and a hardcoded `dueDate: null`. No free-form user input is introduced. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-03 | Tampering / Elevation | `handleInboxDrop` → `bulkUpdateTaskDueDate` | accept | Reuses the existing server action whose handler in `apps/web/app/actions/tasks.ts` enforces `userId` scoping + RLS. A forged ID for another user's task is rejected server-side; this plan adds no new authorization path. |
| T-19-04 | Spoofing | dragged task id origin | accept | `draggedTaskId` is set only from cards rendered from the user's own `optimisticTasks`; the server action re-checks ownership regardless. |
</threat_model>
