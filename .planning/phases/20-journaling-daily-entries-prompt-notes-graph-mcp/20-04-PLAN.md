## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser UI → server action | The editor sends journal text + the selectedDate to upsertJournalEntry; the action (plan 20-02) validates + scopes to the caller. The UI never trusts itself for authorization. |
| Realtime channel → client cache | journal_entries change events drive cache invalidation only; no server-trusted state is derived from the client. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-10 | Information Disclosure | a user expecting privacy but the no_export toggle not actually gating export | mitigate | The toggle writes journal_entries.no_export, which the plan-20-03 loader honors (skip + count); human-verify step 6 confirms persistence; the export gate itself is tested in plan 20-03. |
| T-20-11 | Tampering | autosave race creating duplicate day rows under rapid edits | mitigate | All writes go through upsertJournalEntry's UNIQUE(user_id,date) conflict target; the debounce coalesces edits; plan 20-02 Task 2 proves single-row convergence. |
| T-20-12 | Denial of Service | unbounded history feed query | mitigate | getJournalEntries is bounded by a limit (default 90, max enforced in plan 20-02); the feed renders a capped list. |
</threat_model>
