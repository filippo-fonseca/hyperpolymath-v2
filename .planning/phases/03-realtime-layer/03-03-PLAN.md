Multi-table subscription pattern for CapturesClient (because a capture's hashtag chips and project chips are derived from joins):

```typescript
"use client";
useTableSubscription("captures", userId);             // capture rows
useTableSubscription("captures_hashtags", userId);    // join — drives hashtag count refresh
useTableSubscription("captures_projects", userId);    // join — drives project chip refresh
useTableSubscription("hashtags", userId);             // hashtag rows themselves (new tag auto-create)
```

The `captures_hashtags` subscription invalidates `tableKey("captures_hashtags", userId)`. But the consumer is the `["hashtags", userId]` query (HashtagSidebar) and the `["captures", userId]` query (feed shows chips). So in CapturesClient, on the join-table channel callback we need a CROSS-INVALIDATION via the extended hook:

```typescript
useTableSubscription("captures_hashtags", userId, {
  alsoInvalidate: [tableKey("hashtags", userId), tableKey("captures", userId)],
});
```

Reasoning: D-10 mandates live hashtag count updates when the join changes. The cleanest extension is to add `alsoInvalidate?: ReadonlyArray<readonly [string, string]>` to `useTableSubscription`. This keeps the singleton dedupe + visibility contract intact and only changes WHAT gets invalidated when the channel fires.

// apps/web/app/actions/hashtags.ts (B4 fix — explicit file location + contract)
"use server";
import { createClient } from "@/lib/supabase/server";
import { db } from "@/lib/db";
import { hashtags, captures_hashtags } from "@/lib/db/schema";
import { eq, sql, count } from "drizzle-orm";

export type HashtagWithCount = {
  id: string;
  name: string;
  displayName: string;
  count: number;
};

/**
 * Auth-gated SELECT for the signed-in user's hashtags. Optionally includes
 * the count of captures per hashtag for the HashtagSidebar display.
 *
 * @param options.withCounts - If true, returns HashtagWithCount[]. Otherwise just the rows.
 */
export async function getHashtagsForUserAction(
  options: { withCounts?: boolean } = {},
): Promise<HashtagWithCount[]> {
  const supabase = await createClient();
  const { data: { claims } } = await supabase.auth.getClaims();
  if (!claims) throw new Error("Unauthorized");

  if (options.withCounts) {
    // LEFT JOIN captures_hashtags to count usages
    const rows = await db
      .select({
        id: hashtags.id,
        name: hashtags.name,
        displayName: hashtags.displayName,
        count: sql<number>`coalesce(count(${captures_hashtags.captureId})::int, 0)`,
      })
      .from(hashtags)
      .leftJoin(captures_hashtags, eq(hashtags.id, captures_hashtags.hashtagId))
      .where(eq(hashtags.userId, claims.sub))
      .groupBy(hashtags.id, hashtags.name, hashtags.displayName)
      .orderBy(hashtags.name);
    return rows;
  }

  const rows = await db
    .select({
      id: hashtags.id,
      name: hashtags.name,
      displayName: hashtags.displayName,
      count: sql<number>`0`,
    })
    .from(hashtags)
    .where(eq(hashtags.userId, claims.sub))
    .orderBy(hashtags.name);
  return rows;
}

Hashtag count live update path (D-10):
1. User in window A tags a capture → server inserts into captures_hashtags
2. Realtime emits INSERT on `captures_hashtags` with `user_id=eq.${userId}` filter
3. useTableSubscription("captures_hashtags", userId, { alsoInvalidate: [["hashtags", userId], ["captures", userId]] }) fires
4. ["hashtags", userId] query refetches → HashtagSidebar shows new count
5. ["captures", userId] query refetches → feed cards show new chip
6. Net effect: window B sees both the chip AND the updated count within ~1s

    Step 1 — Extend `apps/web/lib/realtime/useTableSubscription.ts`:
    ```typescript
    // Add to Entry type
    type Entry = {
      channel: RealtimeChannel;
      refcount: number;
      extraKeys: Set<string>;  // serialized JSON of each extra key
    };

    // Update signature
    export function useTableSubscription(
      table: RealtimeTable,
      userId: string,
      options: {
        enabled?: boolean;
        alsoInvalidate?: ReadonlyArray<readonly [string, string]>;
      } = {},
    ): void {
      const enabled = options.enabled ?? true;
      const extraKeysJson = (options.alsoInvalidate ?? []).map((k) => JSON.stringify(k));
      const queryClient = useQueryClient();

      useEffect(() => {
        if (!enabled || !userId) return;
        const key = makeKey(table, userId);
        registerActiveTable(table, userId);

        const existing = channels.get(key);
        if (existing) {
          existing.refcount += 1;
          for (const k of extraKeysJson) existing.extraKeys.add(k);
        } else {
          const extraKeys = new Set<string>(extraKeysJson);
          const supabase = createClient();
          const channel = supabase
            .channel(`rt:${table}:${userId}`)
            .on(
              "postgres_changes",
              { event: "*", schema: "public", table, filter: `user_id=eq.${userId}` },
              () => {
                // Primary key
                void queryClient.invalidateQueries({ queryKey: tableKey(table, userId) });
                // Fanout — D-10 captures_hashtags drives hashtags + captures queries
                const entry = channels.get(key);
                if (entry) {
                  for (const k of entry.extraKeys) {
                    const parsed = JSON.parse(k) as readonly [string, string];
                    void queryClient.invalidateQueries({ queryKey: parsed });
                  }
                }
              },
            )
            .subscribe();
          channels.set(key, { channel, refcount: 1, extraKeys });
        }

        return () => {
          unregisterActiveTable(table, userId);
          const entry = channels.get(key);
          if (!entry) return;
          entry.refcount -= 1;
          if (entry.refcount <= 0) {
            void entry.channel.unsubscribe();
            channels.delete(key);
          }
          // Note: extraKeys are not removed on unmount of one consumer;
          // remaining consumers may still want the fanout. Cleanup of stale
          // keys happens implicitly when refcount → 0 and the entry is deleted.
        };
      // eslint-disable-next-line react-hooks/exhaustive-deps
      }, [table, userId, enabled, queryClient, extraKeysJson.join("|")]);
    }
    ```
