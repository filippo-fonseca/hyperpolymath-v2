<objective>
Fix issue #172: cmd+K JARVIS messages abort when the user navigates to /today mid-stream.

Two-part fix (per JAR-REL-01 through JAR-REL-04):

1. Change GlobalJarvisDialog.handleSubmit to write sessionStorage.setItem("jarvis-prefill", text) and call router.push("/today") instead of dispatching the jarvis-voice-transcript window event. This routes ALL cmd+K submissions through JarvisConsole's existing prefill path, which provides full streaming UI, 5s undo via JarvisReceipt, and proper conversation history — identical behavior to typing directly in the JARVIS tab. Mirrors the LifeOsQuickSend precedent already in the codebase.

2. Remove isConsolePage from the GlobalJarvisHandler useEffect dep array; read it via a ref inside the handler instead. This prevents the effect cleanup from calling abort?.abort() when the user navigates to /today, hardening the voice-turn path as well.

Purpose: After this plan, cmd+K → JARVIS works identically to typing in the tab: streaming visible if user arrives mid-stream (because JarvisConsole handles it directly), 5s undo on every receipt, retry affordance on failed turns (already in JarvisConsole), and proper conversation history passed to Claude.

Output: Two modified source files. Commit atomically.
</objective>
