<objective>
Extend `jarvis_events` with 8 nullable per-stage timestamp columns (D-01), populate the 5 server-side timestamps (`prompt_built_at`, `first_token_at`, `last_token_at`, `tool_loop_done_at` on every turn; `stt_done_at` on voice turns), expose a `turn_id` to the client at stream start so Plan 09-02's voice-stage beacon can correlate, and land the TEL-03 regression guard test.

Purpose: Phase 9 is measurement infrastructure (CONTEXT §domain). This plan ships the server-side half of TEL-01 plus the entirety of TEL-03. Plan 09-02 ships the client-side voice capture + /insights panel (TEL-02). This plan is fully shippable standalone — text-turn LLM telemetry populates 4 columns on every turn, providing a useful baseline for Phase 11 cache work even before voice-pipeline columns are wired.

Output:
- Migration 0017 (additive — 8 nullable timestamptz columns + index)

- `JarvisEventInput` interface + `logJarvisEvent` writer extended with `stages` block
