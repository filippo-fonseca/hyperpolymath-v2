## Decisions Made

- **Plain `jsonb` payload, not `.$type<ContextSnapshot>()`.** Typing the column at the Drizzle level would force a `schema.ts → context/build-snapshot.ts → schema.ts` circular import. Decision: keep the column typeless at the schema layer; Plan 02 will cast at the query site (the planner-approved approach in 999.12-01-PLAN.md Task 3 action notes).
- **No `state_version` trigger on `personal_context_snapshots`.** Snapshot writes come from the cron service role, not user actions, so there's no JARVIS state-cache invalidation requirement. (Contrast: training tables in migration 0024 do fire the trigger.)
- **`--no-verify` on per-task commits.** Per the success criteria explicit instruction "use --no-verify to avoid hook contention; orchestrator validates after". Used on all 3 task commits.
