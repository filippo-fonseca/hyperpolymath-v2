# Phase 999.12 Plan 03: Standalone @hyperpolymath/personal-context-mcp Package Summary

**Standalone MCP workspace package mirroring the packages/jarvis-core factoring — exports `createPersonalContextServer({ userId, loadSnapshot, loadHistory })` returning a configured McpServer with two v1 read-only tools (`get_current_context` topic-filterable + `get_snapshot_history` metadata-only), zero coupling to apps/web, 40 Vitest specs covering node/edge schema acceptance + handler behavior + paramsSchema bounds, and a 231-line PRIVACY.md enumerating the exact exported-field allowlist per node type.**

## Accomplishments

- `packages/personal-context-mcp/` ships as a `private + type=module` pnpm-workspace package mirroring `packages/jarvis-core/` exactly (same `src/index.ts` as both `main` and `types` with no build step, same `exports` map shape with a `./types` sub-path, same Vitest 3 + ES2022 strict TS toolchain).
- `createPersonalContextServer({ userId, loadSnapshot, loadHistory, serverName?, serverVersion? })` returns a fully-configured `McpServer` instance with both v1 tools registered. The server is transport-agnostic — Plan 04 will attach a `StreamableHTTPServerTransport` at the apps/web MCP route boundary. Zero stdio anywhere (the locked transport decision is Streamable HTTP).
- `get_current_context({ topics?: NodeType[] })` returns the latest snapshot (or `"No snapshot available yet."` when the loader returns null), optionally trimmed to the requested node types. Edges are returned in full; filtering is node-only.
- `get_snapshot_history({ days: int 1..30, default 7 })` returns a metadata-only `SnapshotHistoryEntry[]` — `snapshotDate + schemaVersion + nodeCounts + totals`. Full nodes/edges arrays are NEVER included (those can blow the MCP response budget — agents call `get_current_context` for the full payload).
- Loaders are dependency-injected as `LoadSnapshot` / `LoadHistory` callback types — the MCP package never touches the database directly, so it stays deployable in isolation. Plan 04 wires Drizzle-backed implementations at the route layer.
- 40 Vitest specs across two files (25 in `types.test.ts` for every node + edge type accept/reject + schemaVersion = 1 invariant; 15 in `tools.test.ts` for null-snapshot path, full-snapshot path, topic-filter, empty-topics no-op, no-match empty result, history metadata-only assertion, days schema bounds + integer + default + factory smoke). All 40 pass on the first end-to-end run; `tsc --noEmit` green.
- PRIVACY.md is 231 lines (≥60 plan minimum) with seven per-node-type allowlist tables, an explicit deny-list (GCal content, OAuth tokens, integration secrets, jarvis_events telemetry, jarvis_turns scrollback, voice transcripts, no_export rows), the snapshot-immutability + 90-day token-rotation + one-token-per-user-v1 posture, and the forever-snapshot schema-versioning discipline. Open-source-public contract for what data leaves the database.

## Decisions Made

- **Zod schemas duplicated verbatim from apps/web/lib/context/types.ts rather than imported.** MCP-01 requires zero coupling to apps/web so the package can be deployed in isolation. The duplication is small (~70 lines of schema) and the lock-step bump discipline is documented in PRIVACY.md §6 ("when you bump the schema, bump both copies and add a migrator in the apps/web side"). The alternative — lifting the schemas into this package and having apps/web import them — is also viable but reverses the current direction of dependency; deferred to a follow-up cleanup if/when more packages need the types.
- **Tool registration split into makeXHandler(ctx) + registerX(server, ctx).** The plan's <action> for Task 2 explicitly recommends this split so tests can drive handlers directly. The factory returns the bare async handler; the registration wrapper binds it via `server.tool(name, description, paramsShape, cb)`. Tests use the factory exclusively — no McpServer instantiation in the unit tests for the handlers themselves (only one factory-smoke test confirms `createPersonalContextServer` returns an `instanceof McpServer`).
- **@modelcontextprotocol/sdk pinned to ^1.29.0.** `npm view @modelcontextprotocol/sdk version` returned 1.29.0 at install time. The 4-arg `McpServer.tool(name, description, paramsShape, cb)` overload is marked `@deprecated` in favor of `registerTool({ ... })` in this version — the plan uses the deprecated 4-arg form explicitly, and it still works. Migration to `registerTool` is trivial and can happen alongside any future schema-add or output-schema work.
- **Loader callbacks are plain TS types, not Zod schemas.** Inputs are primitives (userId, days); outputs are already Zod-validated by the snapshot builder before they reach the loader boundary. Adding Zod at the loader interface would be double-validation with no benefit.
- **`get_current_context.topics[]` filters NODES ONLY.** Edges are returned in full. Filtering edges would require an O(nodes × edges) walk to drop edges whose endpoints are no longer in the filtered node set; the agent can do that trivially in its own JS layer if it needs that semantics. Returning full edges keeps the package's tool surface predictable and the filter cheap.
- **`get_snapshot_history.days` capped at `.max(30)`.** 30 days is the documented v1 use case (the "last month" query). Larger windows would defeat the metadata-only privacy posture (history grows unboundedly).
- **`get_snapshot_history` returns metadata-only, never the full nodes/edges arrays.** A 30-day window of full payloads at ~500KB each = 15MB, well over MCP tool response budget (RESEARCH.md Pitfall 2). For full payloads, the agent calls `get_current_context`.
- **PRIVACY.md is 231 lines, far over the 60-line minimum.** Open-source-public repository: this file IS the contract. Coverage includes seven per-node-type allowlist tables, explicit deny-list, snapshot-immutability + token-rotation posture, and schema-versioning discipline.
- **`--no-verify` on per-task commits.** Per orchestrator-explicit guidance for parallel execution (the 999.12-04 executor is running in parallel; orchestrator validates hooks once after both finish).
