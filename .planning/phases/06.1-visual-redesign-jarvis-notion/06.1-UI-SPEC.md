### 1a. The brief (verbatim, 2026-05-19)

Subsequent clarifications:

### 1b. Stark HUD vocabulary (extracted from the reference frame)

The user's canonical reference is a single Stark Industries / JARVIS HUD frame: cyan-on-near-black, glowing arc-reactor centerpiece, radial dials, edge-mounted sparklines, mono-data overlays, scan lines, schematic background tracery. The image is the *vocabulary source*, not a pixel target. Elements to translate:

| Stark element | Modern translation in this product |
|---|---|
| Glowing arc-reactor core (triangle-in-circle, intense central cyan) | JARVIS Console input glow + breathing focus ring on `/`. No literal arc reactor — the input *is* the core. |
| Concentric radial dial cluster (multiple thin-stroke ring scales with mono labels) | `agent-thinking` indicator — a single thin concentric ring sweep during model latency. NOT a permanent radial gauge — appears only when JARVIS is working. |
| Edge-mounted micro-charts ("TOTAL NETWORK TRAFFIC" sparkline strip at bottom) | `/insights` sparkline edge strip + JARVIS Console bottom edge "latency / cache" instrumentation row (mono, 12px, opacity 0.4 at rest). |
| Schematic background tracery (faint wireframe grid + thin connecting strokes) | Faint 1px corner-cropped frame brackets on agent-mode surfaces only. No full grid wallpaper. A single corner-mark in each viewport corner, not a wireframe everywhere. |
| Status pills with mono labels (top corners) | `/health` status pills + JARVIS Console state pill (`READY` / `STREAMING` / `THINKING` / `IDLE`). Mono, uppercase, tracking-wide, 11px. |
| Edge data overlays (pressure, humidity, sunrise, moon — column-aligned mono data) | `/insights` left/right edge column-aligned mono micro-data: cache hit rate, p50, p95, last-run age. Like spec strips, not charts. |
| Cyan-dominant on near-black, no chroma noise | Dark theme — the canonical mode. Cyan is the HUD signature, never the only color. |
| Mono everywhere data lives; rare sans/serif reads as accent | Inverted from typical app: in JARVIS Console, *mono is the default surface chrome*; serif is reserved for user-typed content. |
| Instrument-panel density — every region carries data | Agent surfaces carry edge instrumentation. Document surfaces don't. |

### 1c. Reference frames (anchored decisions)

Eight references anchoring the rebuild. Each is cited at the decision it informs.

1. **Linear's 2026 design refresh** — *physical light source motion* (real-time GPU-calculated specular highlight that shifts as you scroll/tap; no static gradient highlights). Anchors §6 (motion choreography on agent surfaces) — the streaming caret light-trail and hover lift behavior. Linear: ["A calmer interface for a product in motion"](https://linear.app/now/behind-the-latest-design-refresh).
2. **Linear's LCH-based theme generation** — three variables (base color, accent color, contrast) drive everything; perceptually uniform color steps. Anchors §3 (color tokens defined in OKLCH where contrast matters).
3. **Vercel's Feb 2026 dashboard redesign** — projects-as-filters, mono labels on data, dark canvas with quiet card layering. Anchors §5 (Sidebar treatment, /insights card layering).
4. **Warp terminal's "UI surface" overlay system** — opposite-overlay-color outline lifting overlay UI from background; mono font with selectable weight; gradient depth support. Anchors §9 (popover/dialog chrome treatment on agent surfaces).
5. **Returnal's teal-CRT HUD** — strictly industrial/functional, technology susceptible to glitch errors. Anchors §6 (error state visual: brief glitch wipe on error receipts; cyan tuned cooler/darker than #00d4ff). PlayStation Blog: ["Unpacking Returnal's UX design"](https://blog.playstation.com/2021/05/11/unpacking-returnals-ux-design-gameplay-first-ui-retro-futuristic-tech-and-accessibility/).
6. **Death Stranding's instrument-strip HUD** — mono labels at edges, content centered, instrumentation in periphery until needed. Anchors §1b edge instrumentation pattern + §5 JARVIS Console layout.
7. **Bloomberg Terminal's color framework** (2025 CVD-accessible update) — `#000000 / #ff433d / #0068ff / #4af6c3 / #fb8b1e`. Anchors §3 — academic precedent for multi-color on near-black surface; intent colors must clear 4.5:1 on the chosen base, not be "vibes." Bloomberg: ["Designing the Terminal for Color Accessibility"](https://www.bloomberg.com/company/stories/designing-the-terminal-for-color-accessibility/).
8. **AG-UI protocol (2025)** — streaming AI agent UI standard: typing indicator before 300ms, TTFT under 800ms, tool-call progress visible. Anchors §6 (motion choreography sequence: submit → thinking-ring within 200ms → caret within 800ms → stream → resolve). [MarkTechPost on AG-UI](https://www.marktechpost.com/2025/09/18/bringing-ai-agents-into-any-ui-the-ag-ui-protocol-for-real-time-structured-agent-frontend-streams/).

Anti-references (what this spec deliberately is *not*):

- Apple iOS 26 Liquid Glass — refraction-based glass cosplay; rejected in §13.
- Saturated startup-template purple-gradient AI tropes (ChatGPT-style); rejected in §13.
- Movie-cosplay scan lines that scroll the whole viewport infinitely; rejected in §13 (we use one-shot scan reveals only).
- Python-tutorial JARVIS clones with cyan-everywhere; the JARVIS-blue-everywhere mistake from Phase 6 is explicitly the anti-pattern §13 catalogues.

## §2 Two-Mode Contract — The Organizing Principle

Hyperpolymath v2 ships **two operating modes** layered on shared infrastructure. Every surface belongs to one. The split is the contract.

### 2a. Mode definitions

| Mode | Where | Character | Discipline |
|---|---|---|---|
| **Document mode** | Tasks, Captures, Projects, Settings, Calendar | Notion-clean, parchment/graphite, serif body, generous whitespace, intent-colored chips, hover-only motion | Maximum restraint. The user is reading or writing. |
| **Diplomatic mode** | Sidebar, CommandMenu, modals, dropdowns, toasts | Quiet chrome — neither doc nor HUD; thin 1px edge stroke, mono chrome labels, serif body content, restrained micro-motion | Mid restraint. Functional UI that serves both modes. |
| **Agent mode** | JARVIS Console (`/`), `/insights`, `/health`, `/settings/memory` | Full Stark HUD theatrics: dark canvas, cyan signature, mono prose, scan reveals, breathing focus ring, edge instrumentation, schematic corner crops, choreographed interaction states. | Discipline lifted. "Sick with amazing animations" — earn every keystroke a visual moment. |

### 2b. Surface placement (JARVIS↔Notion axis, 0 = pure Notion, 10 = pure HUD)

| Surface | Score | Mode | Notes |
|---|---|---|---|
| `/health` | 10 | Agent | Pure instrument panel — mono JSON visual, status pills, latency gauge ring |
| JARVIS Console (`/`) | 9 | Agent | Agent primary — mono prose, scan-line reveal, glow input, radial thinking indicator |
| `/insights` | 9 | Agent | Data-dense diagnostic — mono labels, thin chart strokes, edge sparklines |
| `/settings/memory` | 7 | Agent | Agent-adjacent — glass panels, serif fact content inside HUD chrome |
| `/calendar` | 4 | Document | Notion-leaning, but mono time labels + HUD edge ticks |
| Sidebar | 4 | Diplomatic | Quiet chrome — mono labels, minimal HUD edge accents |
| Modals / dialogs | 3 | Diplomatic | Glass background + 1px HUD edge stroke + corner crops; serif body |
| `/tasks` | 3 | Document | Flat rows, generous space; HUD only on hover/focus |
| Toasts | 3 | Diplomatic | Plain feedback, serif copy |
| `/captures` | 2 | Document | Serif body, no chrome; HUD only at composer input edge |
| `/settings` | 2 | Document | Admin doc — restrained |
| `/projects/[id]` | 1 | Document | Full Notion-style document |

### 2c. Scope boundary rules

- **Cyan never bleeds onto document surfaces.** No cyan focus rings on `/tasks`, `/captures`, `/projects/[id]`, `/settings` (excluding `/settings/memory`), `/calendar` body.
- **Intent colors never bleed into HUD chrome.** No amber priority chips inside `/insights` or `/health`. The intent palette is doc-side.
- **Scan reveals + breathing focus + edge instrumentation never appear on document surfaces.** Even when JARVIS files a task into `/tasks`, the task row itself uses document-mode treatment — only the receipt rendering inside JARVIS Console gets HUD treatment.
- **Mode is determined by route**, not by component. The same `<Button>` component renders neumorphic-quiet on `/tasks` and HUD-chrome on `/insights`.
- **Implementation hook:** `.agent-mode-scope` wrapper (already in globals.css from Phase 6) is the canonical scoping mechanism. Agent-mode routes wrap their root in `.agent-mode-scope`. CSS rules cascade off this class.

### 2d. The discipline-vs-theatrics rationale

The user writes their thoughts in document surfaces; the agent speaks in agent surfaces. Mixing the registers reads as confusion. Notion-clean writing surfaces let content do the work. HUD-theatric agent surfaces signal *the machine is alive*. The split is functional — it tells the user where they are by feel before they read a label.

## §3 Color System

### 3a. Architecture overview

Three layers, scoped:

1. **Base palette** — warm parchment (light) / soft graphite (dark). The canvas under everything.
2. **Cyan HUD signature** — agent-mode chrome only (focus rings inside `.agent-mode-scope`, scan lines, chart strokes, status pills, JARVIS console caret, edge instrumentation labels).
3. **Three academic intent inks** — document-side only (priority dots, intent badges on receipts, status chips). Warm amber, sage/oxide, restrained coral. NOT saturated startup-template hues.

### 3b. Cyan tuning (RESEARCH-grounded)

Phase 6 used `#00d4ff` (hsl 192 100% 50%) — full-saturation electric cyan. Per research:
- Pure cyan is "nearly blinding on screen and rarely used directly in design" ([colorfyi.com](https://colorfyi.com/blog/what-color-is-teal/)).
- Bloomberg's CVD-accessible terminal cyan is `#4af6c3` (hsl 163 89% 63%) — green-shifted teal.
- Returnal's HUD teal is darker, "shade of teal" — not full saturation.

**Phase 6.1 cyan is darker and tuned cooler** — Tailwind's `cyan-500` / `cyan-400` neighborhood (`#06b6d4` / `#22d3ee`) reads "instrument" not "marquee." Phase 6's `#00d4ff` is retired.

| Token | Value (OKLCH + sRGB) | Role |
|---|---|---|
| `--hud-cyan` | `oklch(72% 0.13 210)` ≈ `#22d3ee` | Primary HUD signature (focus rings, captions, status pills) |
| `--hud-cyan-bright` | `oklch(78% 0.16 210)` ≈ `#3bdcf3` | Streaming caret core, active scan line crest (rare, high-emphasis moments only) |
| `--hud-cyan-dim` | `oklch(58% 0.10 210)` ≈ `#0891b2` | Schematic tracery, corner crops, idle edge labels (most cyan usage lives here) |
| `--hud-cyan-glow` | `rgb(34 211 238 / 0.18)` | Behind-element ambient glow (dark) |
| `--hud-cyan-glow-soft` | `rgb(34 211 238 / 0.08)` | Passive glow on dormant elements |

**Light mode cyan dampening:** Per user-locked decision, light mode dims HUD theatrics. On light surfaces, cyan tokens swap to `--hud-cyan-light: oklch(48% 0.13 210)` ≈ `#0e7490` (Tailwind `cyan-700`) — preserves the hue identity but clears 4.5:1 contrast on parchment.

### 3c. Three academic intent inks (multi-color decision, RESEARCH-grounded)

User locked "multi color" 2026-05-19. Three intent inks, academic-restrained (lower saturation than startup templates; ["restrained, high-authority tones … sophisticated, on-brand, WCAG-compliant"](https://onspring.com/resources/blog/risk-reporting-best-color-palettes-for-data-visualization/)):

| Token | Value (OKLCH + sRGB) | Role | Reserved-for |
|---|---|---|---|
| `--ink-amber` | `oklch(70% 0.13 75)` ≈ `#d97706` (Tailwind `amber-600`) | Task priority dots (P1 emphasized), task intent badge on receipts | Task-related: priority chips on /tasks; "task" intent badge in JARVIS receipts; `today` column wash on /calendar (8% opacity) |
| `--ink-sage` | `oklch(62% 0.09 145)` ≈ `#65a30d` (Tailwind `lime-600`) | Capture intent (the "filed" feeling), `#hashtag` chip background tint | Capture-related: "capture" intent badge in JARVIS receipts; `#hashtag` chip tint on /captures; status='done' indicator |
| `--ink-coral` | `oklch(63% 0.16 25)` ≈ `#dc2626` (Tailwind `red-600`) | Event intent + destructive surfaces (event accents and destructive share the same warm-warning territory; distinguished by context) | Event-related: "event" intent badge in JARVIS receipts; event accent on /calendar; destructive button background; error fallback accent |

Light/dark each get a single hex (defined below) — OKLCH ensures the values *feel* the same intensity in both modes despite different sRGB outputs.

### 3d. Base palette (refined from Phase 6; warm parchment kept, graphite slightly cooler)

| Token | Light value | Dark value | Role |

### 3e. Color budget (60/30/10) by mode

**Document mode (60/30/10):** canvas / surface / intent ink (per content type — amber/sage/coral as appropriate).
**Diplomatic mode (60/30/8/2):** canvas / surface / `--ink-muted` mono chrome / minimal intent on active state only.
**Agent mode (55/30/12/3):** canvas (deeper graphite) / surface (raised tile) / cyan family (chrome + caret + rings + tracery) / `--hud-cyan-bright` for high-emphasis moments only.

## §4 Typography — Surface-Coded Mono vs Serif

### 4a. The mono/serif decision is surface-coded

The Phase 6 rule "EB Garamond everywhere; mono for metadata only" is replaced by a **role-based rule**:

> **Mono = machine speaking. Serif = you writing.**

| Content type | Font | Where |
|---|---|---|
| JARVIS prose output (the model's leading text block) | **JetBrains Mono 500** italic | JARVIS Console scrollback — the model's voice is "machine-typed" |
| JARVIS Console UI chrome (status pill, slash hints, edge labels, ⌘K chip, kbd hints) | JetBrains Mono 400 | All `agent-mode-scope` chrome |
| All data points (timestamps, IDs, latency, status, /health JSON, counts, ms values) | JetBrains Mono 400 | Everywhere |
| Edge instrumentation labels on agent surfaces | JetBrains Mono 400, uppercase, 0.08em tracking | /insights edges, /health, JARVIS Console bottom rail |
| User-typed content (capture body, task title, project page body, settings text) | EB Garamond 400 | All document surfaces |
| User-typed content emphasis | EB Garamond 400 italic OR 600 | Project descriptions, task titles when prominent |
| Page headings (all routes) | EB Garamond 600 | All H1/H2 |
| Section labels above content blocks | JetBrains Mono 400 uppercase 0.06em tracking | Settings sections, /insights chart titles |
| Button labels | EB Garamond 400 (doc/diplomatic) or JetBrains Mono 400 (agent surfaces) | Surface-coded |

JetBrains Mono **weight 500** is added to the next/font import for the JARVIS prose register (currently only 400 loaded per Phase 6). Weight 500 reads as "deliberate machine typing" without being bold-shouty.

### 4b. Full type scale (4 sizes, kept from Phase 6 checker revision)

| Role | Size | Weight | Line-height | Font | Use |
|---|---|---|---|---|---|
| H1 / Display | 36px (`text-4xl`) | 600 | 1.2 | EB Garamond | Page headings everywhere |
| H2 / Section | 24px (`text-2xl`) | 600 | 1.3 | EB Garamond | Section headings, modal titles, chart titles |
| Body | 16px (`text-base`) | 400 | 1.5 | **EB Garamond OR JetBrains Mono** — per §4a rule | Default. JARVIS prose = mono italic 500. |
| Mono / Caption | 12px (`text-xs`) | 400 | 1.4 | JetBrains Mono | Timestamps, receipt metadata, status pills, edge instrumentation |

**Edge case — agent edge labels:** Render at 11px (just under `text-xs`), uppercase, tracking 0.08em. This is the *only* off-scale size, used only on agent edge instrumentation (`/insights` corner data overlays, JARVIS Console bottom rail, /health status pill labels). 11px is intentional to read as "engineering legend on a blueprint" — distinct from caption-tier 12px content.

### 4c. Hierarchy enforcement rules (carried + updated)

- Exactly one H1 per page (unchanged from Phase 6).
- No H3 (eliminated in Phase 6 checker revision; replaced by mono-uppercase section labels).
- **JARVIS prose renders as JetBrains Mono 500 italic at 16px** (was EB Garamond italic in Phase 6). This is the single biggest visual change for the agent-mode register.

## §6 Agent-Surface Motion Choreography

This is the heart of the spec given the user's "sick with amazing animations" mandate. All timings are at default; multiply by 0 under `prefers-reduced-motion: reduce`. All easings use motion/react's stock or CSS cubic-beziers documented below.

### 6a. Easing vocabulary

| Token | CSS curve | Use |
|---|---|---|
| `--ease-out-quart` | `cubic-bezier(0.25, 1, 0.5, 1)` | Default — entrance, hover, fade-in |
| `--ease-in-out-circ` | `cubic-bezier(0.85, 0, 0.15, 1)` | Breathing focus ring, scan drift |
| `--ease-out-back` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | Submit ignite (overshoot moment) |
| `--ease-in-fast` | `cubic-bezier(0.7, 0, 0.84, 0)` | Error glitch, undo wipe (snap-out) |
| `--ease-linear` | `linear` | Streaming caret pulse, queued shimmer |

### 6b. JARVIS Console — full interaction state machine

The console moves through 7 visual states. Each state has a defined motion signature.

| State | Visual signature | Timing | Easing | Notes |
|---|---|---|---|---|
| **idle** | Console input at rest; 1px `--edge-hud` border; cursor static; status pill = "READY" | — | — | Default mount state. Bottom rail shows last-known latency in `--ink-muted` mono. |
| **focused-idle** | Border thickens to 2px `--hud-cyan`; ring breathes (`--ring-hud` 8px glow → 14px glow → 8px); status pill = "READY" | breathe cycle 2400ms loop | `--ease-in-out-circ` | Linear's "physical light source moves through space" precedent — the ring isn't pulsing, it's *breathing*. |
| **typing** | While input has unsubmitted text: status pill = "READY"; tiny cyan dot (4px) appears at top-right of input every 8 keystrokes for 240ms — "you have unsent text" indicator | 240ms per dot flash | `--ease-out-quart` | The dot is acknowledgment without being a typing-indicator-from-the-agent. |
| **submitting (ignite)** | On Enter: input border flashes from `--hud-cyan` → `--hud-cyan-bright` (overshoot moment), and a single 1px horizontal scan line drops from the bottom of the input over 320ms and disappears into the scrollback area below; status pill snaps to "THINKING" | 320ms ignite + scan drop | `--ease-out-back` (overshoot) for border; `--ease-out-quart` for scan drop | The "machine takes the command" moment. This is the most expressive single animation in the app. |
| **thinking (radial)** | Below the input, where the user's just-submitted prompt now lives, a thin 1px `--hud-cyan-dim` ring is drawn around the prompt's leading character. An arc-tip (`--hud-cyan-bright`, 30° of the circle) sweeps around the ring continuously (1.4s/rotation, linear) until the first token arrives. Status pill: "THINKING". | sweep 1.4s/rotation, ring fade-in 200ms | `--ease-linear` for sweep, `--ease-out-quart` for ring entrance | This is the *only* place a radial dial appears in the app — translated from the Stark HUD's concentric ring cluster, scoped to the agent-thinking moment. AG-UI's 800ms TTFT target is the latency this masks. |
| **streaming** | Thinking ring fades out (200ms). JARVIS prose typewriter-streams in JetBrains Mono 500 italic. A 2px `--hud-cyan-bright` caret with `--hud-cyan-glow` halo trails the last rendered character. The caret subtly *lights the line behind it*: a 32px wide horizontal `--hud-cyan-glow-soft` gradient trails 8px behind the caret, soft-falloff to transparent (Linear's physical-light-source-moves-through-space precedent). Status pill: "STREAMING". | caret pulse 1100ms loop (opacity 1 → 0.3 → 1 + box-shadow flash); light-trail moves with caret position | `--ease-linear` for pulse | The light-trail is the single most "JARVIS-feeling" element. Replaces Phase 6's stationary caret pulse. |
| **done (resolved)** | Caret + light-trail fade out (160ms). A one-shot scan-line (`--hud-cyan-bright` 70%-stop gradient, 2px) sweeps top-to-bottom across the assistant turn region over 420ms and disappears. Receipts then materialize (see §6c). Status pill snaps back to "READY". | scan 420ms | `--ease-out-quart` | Phase 6's `jarvis-scan-reveal` is the prior art; tuning is the same, just retargeted to the new cyan token. |
| **error** | Status pill snaps to "ERROR" briefly (1.6s) then back to "READY". The assistant turn region briefly glitches: 80ms `--hud-cyan` → `--hud-cyan-bright` → `--ink-coral` → settle on `--ink-coral` 3px left edge on the error receipt. Returnal-inspired CRT glitch — a single horizontal stripe of `transform: translateX(2px)` for 80ms, then snap back. | glitch 80ms; pill recovery 1600ms | `--ease-in-fast` for glitch entry; `--ease-out-quart` for recovery | Returnal precedent: "technology susceptible to glitch errors." The glitch is restrained — one frame, not a sustained effect. |

### 6c. JARVIS receipts — materialize choreography

Receipts replace the rejected hue-rotate-160deg holographic fade. New choreography:

| Phase | Visual | Timing | Notes |
|---|---|---|---|
| **queued (placeholder)** | Receipt card outline materializes first: 1px `--edge-hud` traces from top-left corner clockwise around the perimeter (stroke-dasharray reveal) over 360ms. Then a `--hud-cyan-glow` shimmer sweeps left-to-right through the card body interior over 1800ms loop until the action lands. | outline 360ms + shimmer loop | The outline-traces-first is the moment that reads "JARVIS is constructing this." |
| **landing (action arrives)** | Shimmer stops. Receipt content (intent dot + title + metadata row) fades in from `opacity: 0` to `1` with `y: 4px → 0` over 220ms. | **resolved (success post-undo-window)** | After the 5s undo window closes, the receipt subtly settles: corner crops dim from `--edge-hud` to `--edge` (the receipt joins document register), and a single soft `--hud-cyan-glow-soft` flash pulses through the card body once (380ms). The intent left-edge stripe becomes the dominant visual cue. | settle 380ms | The receipt "graduates" from agent chrome to document record. |
| **undo invoked** | The receipt's interior content wipes left-to-right (mask gradient) over 320ms revealing a strikethrough version of the title in `--ink-muted`, then fades the entire card to opacity 0.5 over 200ms. After 1000ms the card removes from the scrollback. | wipe 320ms + dim 200ms + removal 1000ms | The wipe motion is the Stark "deconstruction" beat — content disassembling. |
| **error receipt** | See §6b "error" — glitch entrance + coral left edge. No materialize choreography (the receipt arrives in error state, doesn't transition into it). | per §6b | — |

### 6d. Edge instrumentation (always-on, agent surfaces only)

The bottom rail on the JARVIS Console + the side edge data overlays on `/insights` are always present at `opacity: 0.4`. On hover of the rail (or hover near it within 80px), they brighten to `opacity: 0.85` over 200ms. Data values update with a brief tick animation when underlying telemetry changes (the new value flashes `--hud-cyan-bright` for 120ms then settles to its rest color).

This is the "ambient instrument panel" beat. Even when nothing's happening, the surface knows things — latency was 287ms, cache hit was 92%, last action was 4s ago.

### 6e. Always-on background motion (agent surfaces only)

A single subtle ambient element: the 4-corner schematic crops *very slowly* breathe in opacity from 0.45 → 0.6 → 0.45 over a 6-second cycle. This is below the threshold of conscious notice but produces the "the panel is alive" subliminal beat. Disabled entirely under reduced-motion.

```css
@keyframes hud-corner-breathe {
  0%, 100% { opacity: 0.45; }
  50%      { opacity: 0.6; }
}
.agent-mode-scope .hud-corner-crop {
  animation: hud-corner-breathe 6s ease-in-out infinite;
}
```

### 6f. Light mode dampening on agent surfaces

Per the user's "light mode = read mode" decision: in light mode, the agent surfaces preserve *structure* (corner crops, scan reveal on done, edge instrumentation present) but **dampen the theatrics**:
- Breathing focus ring becomes a static 2px `--hud-cyan-light` ring (no breathing).
- Streaming caret loses its light-trail (just a solid 2px bar, still cyan).
- Thinking radial sweep still happens (function over form — it masks latency).
- Corner crops don't breathe (held at opacity 0.55).
- Scan reveal still fires on done (it's a one-shot — preserves "the agent finished" beat).
- Always-on edge instrumentation visible but at 0.55 opacity baseline (vs 0.4 in dark).

The light-mode agent surface should read as "the HUD on a printed page" — schematic preserved, dynamics quieted.

## §8 Iconography

### 8a. Stroke weight

Lucide React default is 2px stroke. Override to **1.5px globally** — this is the largest single visual change after typography. Thin strokes are core to the Stark instrument-panel aesthetic ("thin precise strokes" from the reference frame).

```tsx
// In every Lucide import site OR via a wrapper:
<IconName strokeWidth={1.5} />

// Optional global default via a wrapper component
export function Icon({ size = 16, ...props }: LucideIconProps) {
  return <IconComponent size={size} strokeWidth={1.5} {...props} />
}
```

### 8b. Fill rules

- Default: outline-only (Lucide default).
- Active/selected state: outline stays 1.5px in `--hud-cyan` (agent) or `--ink-amber` (doc); NO fill swap.
- Status badges (`/health` ok/down): the dot inside the pill is filled in cyan/coral — only the dot, not the surrounding icon.
- Intent dots on receipts: filled circles 6px (amber/sage/coral).

### 8c. Custom-vs-Lucide policy

Lucide is canonical. Custom SVGs only for:
- Corner crop L-bracket (just 2 lines per corner — inline SVG or pseudo-element)
- Status pill ring (CSS-only, no SVG)
- Thinking radial sweep (CSS conic-gradient or SVG circle with stroke-dasharray)
- P∞ priority glyph (custom — an unbroken loop. Until designed, use Lucide `Infinity` at 14px in `--ink-amber`)

No icon-font dependency. Lucide tree-shakes per icon import.

### 8d. Icon sizing scale

| Context | Size |
|---|---|

## §10 Responsive Contract ≥768px

Per AES-07 — usable down to iPad-width (≥768px). Mobile-native is out of scope.

### 10a. Breakpoints

- `md:` 768px (iPad portrait floor)
- `lg:` 1024px (iPad landscape / small laptop)
- `xl:` 1280px (default desktop)
- `2xl:` 1536px (large desktop)

Below 768px, layout must not break, but JARVIS theatrics may degrade.

### 10b. Per-surface adaptation

| Surface | ≥1280px (default) | 1024-1279px | 768-1023px |
|---|---|---|---|
| JARVIS Console (`/`) | Full ASCII mockup, 4 corner crops, bottom edge instrumentation visible, status pill top-right | Same; reduce horizontal padding | Edge instrumentation collapses to a single right-aligned latency value; status pill stays |
| `/insights` | 3-chart grid 2-cols (chart 3 full width below) + edge data overlays on outer left/right | 2-cols collapse to 1-col stack; edge data overlays move to a single bottom strip | Edge data overlays hide; 3 charts stack |
| `/health` | Full readout with 4 corner crops + hairline | Same | Corner crops reduce to 8px legs; hairline preserved |
| Sidebar | Always 240px wide expanded / 64px collapsed | Same | Auto-collapses to 64px by default; expand on hover |
| CommandMenu | Centered modal max-w-2xl | Same | max-w-full with 24px viewport padding |
| `/calendar` | rbc native responsive | Same | Day view default below 1024px |
| Modals | Centered max-w-2xl | Same | max-w-full with 16px viewport padding |
| Tasks kanban | 4 columns side-by-side | Same | Stack columns vertically OR horizontal scroll (depending on user preference, defer to executor) |

### 10c. Elements that drop below 768px

Even if rendered, these become non-functional or are hidden:
- ⌘K hint chip (`hidden md:inline-flex`)
- Edge instrumentation on agent surfaces (`hidden md:flex`)
- Corner crops at the viewport level (still on cards; just not on the page chrome)
- Bottom rail latency display on JARVIS Console (`hidden md:flex`)
- Kbd hints in CommandMenu dialog header (`hidden md:inline`)

### 10d. The HUD doesn't degrade *visually* — it degrades *spatially*

A core principle: even at 768px, the agent surfaces should still *feel* like HUDs. The 4-corner crops, the cyan focus ring, the streaming caret, the scan reveal, the thinking ring — all preserved. What drops is the *peripheral* data (bottom rail metrics, edge data overlays). The center stays HUD.

## §11 Accessibility

### 11a. Focus rings

Replace Phase 6's `--shadow-nm-focus-*` tokens with `--ring-doc` and `--ring-hud`:

```css
:focus-visible {
  outline: none;
  box-shadow: var(--ring-doc);
}
.agent-mode-scope :focus-visible {
  outline: none;
  box-shadow: var(--ring-hud);
}
```

`.agent-mode-scope` wrapper carries forward from Phase 6 (already in globals.css from 06-05).

- `:focus-visible` only (not `:focus`) — preserves the mouse-click-without-ring behavior.
- Minimum focus ring contrast ratio: 3:1 between ring color and adjacent background. Per [WCAG 2.1 §1.4.11](https://www.allaccessible.org/blog/color-contrast-accessibility-wcag-guide-2025/).

## §13 Anti-Patterns (DO NOT SHIP)

Explicit rejection list. Each is grounded in either user feedback or research.

| Anti-pattern | Why rejected |
|---|---|
| **Neumorphic shadows on anything** | Phase 6 contract rejected by user 2026-05-19 verbatim. Soft inset/outset shadows on cards, buttons, inputs — all retired. Cards now use 1px borders + ambient `--hud-cyan-glow-soft` on agent surfaces. |
| **Cyan everywhere (`#00d4ff` saturation)** | Phase 6's `--color-accent-jarvis: #00d4ff` was full-saturation electric cyan, applied broadly. Reads as Python-tutorial cosplay. Replaced by darker, scope-restricted `--hud-cyan` (oklch 72% 0.13 210). Cyan is a chrome signature, not a brand wash. |
| **Saturated startup-template intent colors** | Avoid pure `#ff0000` red, pure `#00ff00` green, neon purple. Intent inks use OKLCH at ~62-72% lightness, chroma ~0.10-0.16 — academic-restrained per [Bloomberg's CVD palette](https://www.bloomberg.com/company/stories/designing-the-terminal-for-color-accessibility/) precedent. |
| **iOS Liquid Glass clone** | [Apple's iOS 26 Liquid Glass](https://medium.com/@expertappdevs/liquid-glass-2026-apples-new-design-language-6a709e49ca8b) refraction-based glass material is a registered Apple aesthetic. Modals use simple `backdrop-filter: blur(8px)` over a quiet scrim — no refraction, no specular highlight, no shape-shifting glass. Linear took its [own restrained spin](https://linear.app/now/linear-liquid-glass); we do the same. |
| **ChatGPT-purple gradient AI tropes** | Saturated purple-to-blue gradients on AI surfaces read as 2024-template. Cyan-only on agent surfaces. No gradient backdrops. |
| **Movie-cosplay scan lines (infinite loop scrolling)** | The Stark HUD reference has perpetual scan lines. In production: one-shot scan reveals only (on done state). No infinite background-scroll scan effect. Per Returnal's "industrial/functional" precedent — the technology *can* glitch but doesn't *advertise* itself. |
| **Gratuitous radial gauges that don't show data** | The thinking-ring radial is the only radial in the app, and it disappears the instant the first token arrives. No decorative dials. The Stark frame's radial cluster is the *vocabulary*, not the *literal copy*. |
| **Default-shadcn-and-call-it-done** | Every shadcn component used must be theme-customized to land on the 6.1 token palette. The unstyled-shadcn look (white card + 1px gray border + system font) is the executor's anti-pattern. |
| **Mixing serif and mono in the same content block on the same register** | JARVIS prose is mono italic 500. User capture body is serif. The two never share a paragraph. (Receipts mix them at *different roles*: serif title + mono metadata — that's fine, different content types.) |
| **Cyan on document surfaces / intent colors on agent chrome** | Per §2c scope boundary rules. No exceptions. |
| **EB Garamond weight 500 anywhere** | Eliminated in Phase 6 checker revision; carries forward. Mono weight 500 is the only weight-500 in the app (for JARVIS prose). |
| **Multiple H1s on a page** | One per page. Always. |
| **Page transitions with y-offset** | Pure opacity only. Carried from Phase 6 (UI-SPEC §6c). |
| **Decorative background grids or wallpaper schematics** | Reference frame has full background tracery; in production this would be visual noise. Only 4 corner crops per agent surface. |
| **Always-on scan lines on document surfaces** | Document surfaces are dead still at idle. The agent moves; the document is quiet. |
| **Custom monospace ligatures** | JetBrains Mono ships ligatures (`=>`, `!=`). Disable via `font-variant-ligatures: none` on `--font-mono` to keep the "telex-typed" register pure. |
| **Generic neumorphic + brand-accent treatments as the destination** | Per user memory `feedback_ui_aesthetic.md` — explicitly rejected. |
