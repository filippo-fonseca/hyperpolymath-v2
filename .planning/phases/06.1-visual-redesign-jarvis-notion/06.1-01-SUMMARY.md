# Phase 06.1 Plan 01: Token Foundation + Motion Library + HUD Primitives

**Phase 6.1's entire substrate landed in one plan: OKLCH base palette + HUD cyan family + three academic intent inks + focus ring tokens + motion easing tokens + 12 @keyframes + 10 motion utility classes + prefers-reduced-motion guards + JetBrains Mono 500 italic + ThemeToggle migration + two shared HUD primitives. Waves 2-4 can now consume `var(--hud-cyan)`, `var(--ring-hud)`, `.hud-thinking-sweep`, `<HudCornerCrops />`, `<HudEdgeInstrumentation />` directly without re-derivation.**

## Accomplishments

### Task 1 — Token foundation rewrite (globals.css)

Retired Phase 6's neumorphic + cyan-everywhere token set wholesale:

- Deleted from `@theme` block: `--color-accent-jarvis`, `--color-accent-jarvis-glow`, all 7 `--shadow-nm-*` tokens (surface, button, button-hover, button-active, input, focus-journal, focus-agent), Phase 6's warm-amber `--color-accent` + `--color-ring`
- Deleted from `.dark` block: same set
- Deleted the `.agent-glow-passive` utility class

Installed Phase 6.1's canonical token set in `@theme`:

- **Base palette** (warm parchment light): `--canvas`, `--surface`, `--surface-raised`, `--ink`, `--ink-muted`, `--edge`, `--edge-hud` — all OKLCH
- **HUD cyan family**: `--hud-cyan` (oklch(72% 0.13 210)), `--hud-cyan-bright`, `--hud-cyan-dim`, `--hud-cyan-light` (oklch(48% 0.13 210), dampened for light-mode 4.5:1 contrast per §3b), `--hud-cyan-glow` (rgb(34 211 238 / 0.18)), `--hud-cyan-glow-soft`
- **Three academic intent inks**: `--ink-amber`, `--ink-sage`, `--ink-coral` (oklch 62-70% lightness, Bloomberg CVD-accessible palette precedent)
- **Focus ring tokens**: `--ring-doc` (amber, doc surfaces), `--ring-hud` (cyan + glow, agent surfaces)
- **Motion easing**: `--ease-out-quart`, `--ease-in-out-circ`, `--ease-out-back`, `--ease-in-fast`
- **Tailwind 4 `--color-*` bindings** rewired to consume new palette via `var()` (preserved names, new source values)

Dark mode (`.dark` block) gets cool-ink OKLCH variants:

- `--canvas: oklch(15% 0.005 240)` through `--edge: oklch(28% 0.008 240)`
- HUD cyan family identical to light (electric blue reads the same in both)
- Intent inks slightly lifted (e.g., `--ink-amber: oklch(72% 0.12 75)`)
- `--ring-hud` gets a 10px glow term in dark (vs 8px light)

Appended `@media (prefers-contrast: more)` block per §11d — escalates `--edge`, `--edge-hud`, `--ink-muted` for both themes.

Replaced `:focus-visible` rule pair to consume `--ring-doc` / `--ring-hud` (mechanism unchanged — two-tier rule with `.agent-mode-scope` scoping; only the box-shadow values move).

**Commit:** `5e9f4d9 feat(06.1-01): install Phase 6.1 token foundation in globals.css`

### Task 4 — Shared HUD primitives for Wave 2 parallel race

Created two shared primitives in `apps/web/components/shared/`:

**HudCornerCrops** (`HudCornerCrops.tsx`):
- Props: `size` (default 12px), `className` (default `absolute inset-0 pointer-events-none`), `breathing` (default true)
- Four `<svg>` L-brackets stroked 1px at `var(--edge-hud)`
- `breathing=true` applies `.hud-corner-crop` class (6s opacity loop via `--ease-in-out-circ`)
- `breathing=false` renders static (used by Plan 03 chart panels)
- `aria-hidden="true"` on wrapper + each `<svg>` (purely visual chrome)

**HudEdgeInstrumentation** (`HudEdgeInstrumentation.tsx`):
- Props: `latencyMs`, `cacheHitPercent`, `lastTurnRelative` (all nullable), `className`
- Mono 11px uppercase `tracking-[0.08em]` `--ink-muted` rail with bracket glyphs (╶── ──╴) and · separators
- `useTickOnChange<T>(value)` hook fires `.hud-edge-tick` 120ms color flash on each prop change (referential inequality + setTimeout)
- `hidden md:flex` per §10c (drops below 768px to preserve mobile vertical space)
- `opacity-40` at rest → `hover:opacity-85` (§6d hover-brighten)
- `aria-hidden="true"` (decorative — underlying data is on `/insights`)

These primitives land in Wave 1 (not Wave 2) deliberately: both Plan 02 (JARVIS Console chrome) AND Plan 03 (/insights chart panels + /health viewport + /settings/memory) consume them. By landing them as Wave 1 prerequisites, the two Wave 2 plans can run in parallel without race conditions. JARVIS-Console-specific primitives (HudStatusPill, HudThinkingRing) stay in Plan 02 because they encode the 6-state console state machine.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Convention] Biome style enforcement on new + modified TS files**

- **Found during:** Task 4 (and Task 3 retroactively)
- **Issue:** Newly created HudCornerCrops.tsx, HudEdgeInstrumentation.tsx, and modified ThemeToggle.tsx used single-quoted strings while `biome.json` declares `"quoteStyle": "double"`. Biome also flagged `<svg>` elements as needing accessibility hints and `<button role="radio">` as a semantic-element opportunity.
- **Fix:**
  - Ran `pnpm biome check --fix` on the 3 TS files this plan touches → biome rewrote single quotes to double quotes and applied formatter rules (e.g., compact ternary on `<Sun/>` vs `<Moon/>` icons)
  - Added `aria-hidden="true"` to each `<svg>` in HudCornerCrops so they don't need their own `<title>` element (the wrapper `<div>` is already `aria-hidden`, so this is correctness, not just lint-silencing)
  - Added an explicit `biome-ignore lint/a11y/useSemanticElements:` comment on the segmented-control buttons in ThemeToggle — the `<button role="radio">` pattern is the canonical Radix/shadcn approach for visually styled radio groups (native `<input type="radio">` would force browser chrome that fights the design)
- **Files modified:** apps/web/components/shared/HudCornerCrops.tsx, apps/web/components/shared/HudEdgeInstrumentation.tsx, apps/web/components/shell/ThemeToggle.tsx
- **Commit:** d6b318a (Task 4 commit folded the biome cleanup in)
