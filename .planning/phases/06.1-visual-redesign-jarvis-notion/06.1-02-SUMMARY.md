# Phase 06.1 Plan 02: JARVIS Console Motion Choreography Rebuild

**The flagship plan of Phase 6.1. The user's "sick with amazing animations and feel awesome" felt-quality mandate lives or dies here — and it ships. The JARVIS Console now renders a fully-choreographed 7-state interaction machine: every keystroke, focus, submit, thinking, streaming, done, and error event earns a visual moment. Two new shared HUD primitives (HudStatusPill, HudThinkingRing) join Plan 01's HudCornerCrops + HudEdgeInstrumentation to form the building blocks Waves 2-4 reuse on /insights, /health, /settings/memory.**

### Task 1 — JARVIS-specific HUD primitives + Console chrome mount

**Created `apps/web/components/shared/HudStatusPill.tsx`:**

6-state pill (`ready` / `sending` / `thinking` / `streaming` / `error` / `undo`) with per-state color triples (dot / text / border) plus the `streaming` state's `--hud-cyan-glow` background. The Motion 12 `<motion.span key={state}>` pattern triggers a 240ms scale-pulse `[1, 1.4, 1]` on every state change without any imperative useEffect — Motion remounts the element on key change. `aria-live="polite"` announces state changes via the `aria-label="JARVIS status: {state}"` template.

**Created `apps/web/components/shared/HudThinkingRing.tsx`:**

Two-layer SVG: a static 1px `--hud-cyan-dim` background ring, plus a rotating 1.5px `--hud-cyan-bright` arc tip computed as a 30° dasharray segment (`circumference * (30/360)` arc, remainder as gap). The arc-tip group gets `.hud-thinking-sweep` (Plan 01 keyframe — 1.4s/rotation linear loop). Reduced-motion `useReducedMotion()` strips the sweep class so the arc freezes at 12 o'clock — still indicates "working" without rotation.

**Modified `apps/web/components/jarvis/JarvisConsole.tsx`:**

- Added `relative` to the `.agent-mode-scope` wrapper so the absolutely-positioned chrome anchors to the console viewport (not the page)
- Mounted `<HudCornerCrops size={12} />` as the first child of the wrapper (4 viewport-corner L-brackets, breathing 6s loop via Plan 01's keyframe)
- Mounted `<HudStatusPill state={status} className="absolute top-4 right-4 z-10" />` driven by the new `status: HudStatusState` derived value
- Mounted `<HudEdgeInstrumentation />` in a centered flex row below the input
- Derived `status` via `useMemo([turns, streaming])`: walk turns from the end looking for the most-recent assistant turn; `status='error'` → `'error'`, `status='streaming'` + `textDelta.length > 0` → `'streaming'`, `status='streaming'` + no textDelta → `'thinking'`, no governing turn → `'sending'` if `streaming=true` else `'ready'`

### Task 2 — JarvisInput state machine rebuild (states 1-4)

**Modified `apps/web/components/jarvis/JarvisInput.tsx`:**

Added 5 state variables: `isFocused`, `hasContent`, `igniting`, `keystrokeCount`, `typingDotVisible`. Added `useReducedMotion()` hook. Wired TipTap focus/blur/update events to drive `isFocused`, `hasContent`, and `keystrokeCount`. Added a separate useEffect that fires the typing dot for 240ms whenever `keystrokeCount % 8 === 0 && hasContent`.

**State 1 (idle):** 1px `--edge-hud` border, no animations.

**State 2 (focused-idle):** Derived flag `focusedIdle = isFocused && !hasContent`. Border thickens to 2px `--hud-cyan`. Class `.hud-focus-breathe` applies (gated by `!shouldReduce`) — the Plan 01 keyframe breathes the ring 8px → 14px → 8px on a 2400ms loop via `--ease-in-out-circ`.

**State 3 (typing):** Border stays 2px `--hud-cyan`. Every 8 keystrokes, a 4px cyan dot fades in top-right of input for 240ms via Motion 12 `AnimatePresence` with `--ease-out-quart`.

**State 4 (submitting-ignite):** On `submitFromView`, `setIgniting(true)` triggers two simultaneous animations:
1. Wrapper className picks up `.hud-submit-ignite-border` (gated by `!shouldReduce`) — 320ms cyan → cyan-bright → cyan flash with `--ease-out-back` overshoot
2. Child scan-drop element mounts via `AnimatePresence` — a 1px `--hud-cyan-bright` horizontal line with `0 0 8px var(--hud-cyan-glow)` box-shadow drops 80px over 320ms with opacity 1 → 0 via `--ease-out-quart`

`setTimeout(() => setIgniting(false), 320)` clears the flag after the window. `setKeystrokeCount(0)` + `setHasContent(false)` reset so the next session starts fresh.

**Placeholder copy:** Updated from `"Type a sentence — JARVIS will route it."` to `"what shall we file?"` per UI-SPEC §5a (lowercase JARVIS-prompt register, no period).

**⌘K hint chip:** Restyled from Phase 6's `text-xs opacity-50` to mono 11px uppercase tracking-`[0.08em]`, 1px `--edge-hud` border, `--surface` bg per UI-SPEC §9e.

**Bottom hint row:** Restyled from `font-sans text-[12px] text-muted-foreground` to `font-mono text-[11px] text-[var(--ink-muted)]`; copy lowercased.
