<discovery_findings>
**AreasTree render strategy (Task 1 prereq):**
- Hybrid: cards are flex DOM (`flex items-start gap-8 ... min-w-min w-fit`) inside `overflow-x-auto`. Connectors are an absolutely positioned `<svg>` covering the container, with per-card orthogonal paths computed from `getBoundingClientRect()` via ResizeObserver.
- Trunk: vertical drop from root avatar to a single `junctionY = rootBottom + TRUNK_DROP`.
- Junction: ONE horizontal `<line>` spanning `minX → maxX` at `junctionY`.
- Per-card path: `M rootCx rootBottom V junctionY H cardCx V (cardTop - 2)` (or trunk-only for single-card case).
- Animated feed dots use `<animateMotion mpath=#feed-path-{id}>`.
- This means: switching the row from `overflow-x-auto nowrap` to `flex-wrap` BREAKS the single junction line (it stays at one Y while cards now occupy multiple rows). Per-card paths also break (they still route through the old junctionY).
- Minimal fix: bucket cards into rows by their `top` coordinate after measurement; for each row, emit one junction segment at that row's `top - TRUNK_DROP/2` (or similar), and route each card's branch from row-junction-Y down to card top. Trunk from root drops to FIRST row's junction; subsequent rows are connected by a vertical SPINE down the rootCx between rows.

**JARVIS turn endpoint (Task 3 prereq):**
- `POST /api/jarvis` — SSE, consumed via `streamJarvis(payload, callbacks, signal, voiceActive)` exported from `apps/web/components/jarvis/jarvis-stream-client.ts`.
- Payload shape `JarvisRequest`: `{ input: string, history: {role, content}[], parsedDates?, parsedPriority?, slashCommand?, linkedProjectIds?, linkedHashtags? }`.
- Heavy `JarvisConsole` owns scrollback, voice plumbing, HUD chrome. NOT mountable lightly on /lifeos.
- Strategy: prefill handoff via `sessionStorage.setItem('jarvis-prefill', text)` + `router.push('/today')`. JarvisConsole consumes once on mount in a useEffect.

**Existing JARVIS input component (Task 4 prereq):**
- `JarvisInput.tsx` is heavy: TipTap + dual Mention extensions + slash popover + ignite state machine + module-level focus singleton (registerJarvisFocus). NOT cleanly reusable in a Cmd+K dialog without dragging project/hashtag fetches.
- `GlobalHotkeys.tsx` already binds Cmd+K → `focusJarvis()` (no-op when console isn't mounted).
- Strategy: build a shared `LiteJarvisComposer` (plain `<textarea>` + autosize + Cmd+Enter) used by BOTH Task 3 (inline on /lifeos) AND Task 4 (Cmd+K dialog). The dialog is suppressed when pathname starts with `/today` (focusJarvis path wins there). GlobalHotkeys is amended to fire a `jarvis-dialog-open` custom event when no focus target is registered.
