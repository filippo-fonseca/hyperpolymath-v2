# Quick Task 260615-n2d: Show associated area in project assignment dropdown on tasks

Closes [#39](https://github.com/filippo-fonseca/hyperpolymath-v2/issues/39).

## Problem
The project-assignment dropdown on the task view (`ProjectAutocomplete` rendered inside `TaskDetailPanel`) shows only the project name (and course code for classes). When multiple projects share similar names — or when the user organizes by area — there is no signal of which area a project belongs to.

## Approach
Surface the project's area inline in each `CommandItem`, right-aligned and dim, so it reads as a secondary affordance rather than competing visual weight.

1. Extend the two server-side queries that feed the dropdown to LEFT JOIN `areas` and select `areaName` / `areaEmoji`:
   - `apps/web/app/(app)/tasks/page.tsx` (drives `/tasks`).
   - `apps/web/app/(app)/projects/[projectId]/page.tsx` (drives `ProjectTasksSection` on the project detail page, which reuses the same `TaskDetailPanel` + `ProjectAutocomplete`).
2. Thread the two new fields through the prop types:
   - `TasksClient` `Props.projects`
   - `ProjectDetailClient` `Props.activeProjectsForComposer`
   - `ProjectTasksSection` `Props.projects`
   - `TaskDetailPanel` `ProjectOption`
   - `ProjectAutocomplete` `ProjectOption`
3. In `ProjectAutocomplete` render a right-aligned `<span>` per item showing `{emoji} {areaName}`, using `text-[var(--ink-muted)]` so it sits quietly behind the project name. When `areaName` is null (defensive — schema has `projects.areaId` NOT NULL), render "No area" in italic + 70% opacity so the row still aligns and reads gracefully.
4. Extend the `CommandItem` `value` (the field shadcn's `Command` searches against) to include the area name, so typing an area in the search filters projects under it.

## Tasks

### 1. SSR queries pull area
- Files: `apps/web/app/(app)/tasks/page.tsx`, `apps/web/app/(app)/projects/[projectId]/page.tsx`
- Action: import `areas` from `@/lib/db/schema`; add `.leftJoin(areas, eq(projects.areaId, areas.id))` and select `areaName: areas.name, areaEmoji: areas.emoji`.
- Verify: `pnpm typecheck` passes; new fields appear on the SSR-derived prop without breaking existing call sites.

### 2. Prop types carry area through
- Files: `TasksClient.tsx`, `ProjectDetailClient.tsx`, `ProjectTasksSection.tsx`, `TaskDetailPanel.tsx`, `ProjectAutocomplete.tsx`
- Action: add `areaName: string | null` and `areaEmoji: string | null` (or `?:` on the leaf `ProjectOption` interface) to each project-shape definition. Other consumers (`TaskFilters`) take a narrower `{ id, name }` shape and stay compatible via structural subtyping.
- Verify: `pnpm typecheck` clean.

### 3. Render area inline in the dropdown item
- File: `apps/web/components/tasks/ProjectAutocomplete.tsx`
- Action: inside the `projects.map` rendering, wrap the project name in a `<span class="truncate">` and add a right-aligned `<span class="ml-auto pl-2 shrink-0 truncate text-[12px] text-[var(--ink-muted)]">` with `{areaEmoji} {areaName}` (italic + 70% opacity fallback "No area"). Update the `value` prop passed to `CommandItem` to include the area name so search matches area queries.
- Verify: dropdown opens; each row shows project name on the left, area on the right; "No area" renders for any orphan; layout doesn't wrap or grow.

## Must-haves
- Every project entry shows its area name without hover or extra interaction (acceptance note 1).
- Projects with no area render gracefully — "No area" placeholder, same row height (acceptance note 2).
- Visual weight stays subordinate to the project name — secondary line uses `--ink-muted` at 12px, no additional borders/badges (acceptance note 3).
- TypeScript: `pnpm typecheck` shows no new errors in modified files.
