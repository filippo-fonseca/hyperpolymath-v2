# Summary — Issue #43

Two tight token-level fixes on Jarvis surfaces, both rooted in design-system drift.

## What changed

### 1. Hashtag chip backgrounds → brand sage (commit `21fb795`)

`globals.css` and `HashtagChip.tsx` were using raw Tailwind `rgb(101 163 13 / X)` (lime-600) as the chip background while pairing it with `--ink-sage` text. The lime is a fluorescent yellow-green that reads as off-brand against the parchment palette. Replaced with `color-mix(in oklch, var(--ink-sage) X%, transparent)` so the bg derives from the actual brand sage ink token. Same alpha ladder (idle 12% / hover 22% / selected 32%). Selected-state text bumped from `--ink-sage` to `--ink` for legibility on the deeper tint.

Files:
- `apps/web/app/globals.css` (`.hashtag-chip-inline`, `.hashtag-chip-live`)
- `apps/web/components/captures/HashtagChip.tsx`

### 2. Input/Textarea focus border → match global ring (commit `29f724b`)

The global `input:focus-visible` / `textarea:focus-visible` rule in `globals.css` already paints both border-color and the focus ring as the calm neutral `--edge-hud` (intentional, see the §"Focus-visible ring system" comment — text fields are too high-traffic for the amber doc ring). The `Input` and `Textarea` primitives were independently overriding focus border to `--ink-amber`, producing an inconsistent amber-border-inside-cyan-ring focus state on every non-Jarvis input. Removed the override so the global rule comes through clean.

Files:
- `apps/web/components/ui/input.tsx`
- `apps/web/components/ui/textarea.tsx`

## What didn't change

- **Project chip** (`.project-chip-inline`) — amber, intentional, not in the complaint.
- **Jarvis input itself** — cyan border + ring inline-styled in `JarvisInput.tsx`. Agent-mode signature, untouched.
- **`aria-invalid` coral border** — still applies on Input/Textarea.
- **No new design tokens** introduced; everything reuses `--ink-sage` / `--edge-hud` / `--ink`.
