<objective>
Harden `apps/web/lib/link-preview/fetch.ts` (GitHub issue #261) against two server-side vulnerabilities in the link-preview fetcher: (1) SSRF — no host/DNS private-IP filter and `redirect: "follow"` lets a public URL redirect into an internal target (cloud metadata 169.254.169.254, localhost, RFC1918); (2) unbounded body — `fetchGeneric` buffers the entire response via `await res.arrayBuffer()` before slicing, so a hostile huge response can exhaust memory.

Purpose: Close the SSRF and memory-exhaustion holes without regressing any existing behavior (6s timeout, MAX_HTML_BYTES=1.5MB, user-agent, content-type gating, relative og:image resolution, and the "never throws — always returns a LinkPreviewResult" contract).

Output: A new self-contained `ssrf.ts` helper (Node built-ins only, no npm deps), a hardened `fetch.ts` (per-hop host guard + manual bounded redirects + streamed size cap), and a pure unit test file for the IP classifier.
</objective>

  <name>Task 1: SSRF IP classifier + async host guard (new ssrf.ts)</name>
  <files>apps/web/lib/link-preview/ssrf.ts, apps/web/tests/link-preview-ssrf.test.ts</files>
  <behavior>
    isPrivateAddress(ip) returns true (blocked) for representative addresses:
    - IPv4: 127.0.0.1 (loopback), 10.0.0.1 (RFC1918), 172.16.0.1 (RFC1918), 192.168.1.1 (RFC1918), 169.254.169.254 (link-local / cloud metadata), 0.0.0.0, 100.64.0.1 (CGNAT), 192.0.2.1 (TEST-NET), 240.0.0.1 (reserved)
    - IPv6: ::1 (loopback), fc00::1 and fd00::1 (unique-local), fe80::1 (link-local), :: (unspecified)
    - IPv4-mapped IPv6: ::ffff:127.0.0.1 and ::ffff:169.254.169.254 must be blocked (map to blocked v4)
    isPrivateAddress(ip) returns false (allowed) for public addresses: 8.8.8.8, 1.1.1.1, 2606:4700:4700::1111 (public IPv6), 2001:4860:4860::8888
    An unrecognized / non-IP string returns true (fail-closed — treat as unsafe).
    assertHostAllowed(url) resolves (does not throw) for a public host and rejects (throws an Error) when the host is an IP literal in a blocked range OR any DNS-resolved address is blocked.
  </behavior>
  <action>
    Create `apps/web/lib/link-preview/ssrf.ts` — pure Node built-ins only (`node:net` for `isIP`, `node:dns/promises` for `lookup`), no npm dependencies.

    Export `isPrivateAddress(ip: string): boolean`. Use `isIP(ip)` to branch:
    - Family 4: split into four octets (Number). Reject (return true) when: first octet is 0 (0.0.0.0/8) or 127 (loopback) or 10 (RFC1918); octets are 169 && 254 (link-local, covers metadata 169.254.169.254 — note this range explicitly in a comment); 172 && second octet in 16..31 (RFC1918); 192 && 168 (RFC1918); 100 && second octet in 64..127 (CGNAT 100.64.0.0/10); 192 && 0 && 2 (TEST-NET-1 192.0.2.0/24); first octet >= 224 (multicast 224/4 and reserved 240/4, i.e. anything not a normal unicast public range). Otherwise return false.
    - Family 6: lowercase the address. First, detect an IPv4-mapped form: if it matches `::ffff:` followed by a dotted-quad, extract the trailing IPv4 and delegate to the IPv4 branch of isPrivateAddress. Also handle the case where Node normalizes a mapped address to hex (rare) by not relying on it. Then reject (return true) for: `::1` (loopback), `::` (unspecified), a first hextet of `fe80`..`febf` (link-local fe80::/10), and a first hextet whose high bits mark unique-local (`fc00::/7`, i.e. first byte 0xfc or 0xfd — match a leading `fc` or `fd`). Otherwise return false.
    - Not an IP at all (isIP returns 0): return true (fail-closed).

    Export `async function assertHostAllowed(url: URL): Promise<void>`. Read `url.hostname`. Strip surrounding brackets from IPv6 literals (`[::1]` → `::1`). If `isIP(host)` is nonzero, call `isPrivateAddress(host)` and throw `new Error("Blocked address: <host>")` if true; return otherwise. If it is a hostname, `await lookup(host, { all: true })` to get every A/AAAA record, and if the lookup yields zero addresses OR `isPrivateAddress` is true for ANY resolved `address`, throw `new Error("Blocked host resolves to private address: <host>")`. This guards DNS-rebinding by rejecting when any resolved address is unsafe.

    Do NOT inline sample IP literals that a test negative-greps for into head-comment prose. Keep comments conceptual.

    Then create `apps/web/tests/link-preview-ssrf.test.ts` (pure unit, NO network — only exercise `isPrivateAddress`, never `assertHostAllowed`'s DNS path). Mirror the existing describe/it/expect style of `apps/web/tests/link-preview-classify.test.ts`. One describe block asserting every blocked address from <behavior> returns true and every allowed address returns false, plus the fail-closed non-IP case.
  </action>
  <verify>
    <automated>pnpm --filter web test -- link-preview-ssrf</automated>
  </verify>
  <done>ssrf.ts exports isPrivateAddress + assertHostAllowed; link-preview-ssrf.test.ts passes with all blocked addresses (incl. 169.254.169.254, ::1, fc00::1, ::ffff:169.254.169.254, 172.16.0.1) returning true and public addresses (8.8.8.8, 1.1.1.1, public IPv6) returning false; no network access in the test.</done>

    - Keep the existing 6s `FETCH_TIMEOUT_MS` AbortController + `clearTimeout` in `finally` semantics, and the same headers (`user-agent`: USER_AGENT, `accept`). Reuse ONE AbortController across all hops so the total time budget still caps at 6s.

    - Before EACH fetch (initial URL and every redirect target): parse the current URL with `safeParseUrl`; if it is null or its protocol is not http:/https:, throw `new Error("Unsupported redirect target")`; then `await assertHostAllowed(parsedUrl)`. If the redirect budget is exhausted, throw `new Error("Too many redirects")`.

Do NOT add try/catch inside fetchWithTimeout that swallows the error — let it propagate to the existing catch in `fetchLinkPreview`. `fetchOEmbed` already catches and returns null, so blocked oEmbed hosts degrade there too.
