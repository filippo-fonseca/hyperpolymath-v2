# Quick Task 260615-n1x: Hashtags render as styled tokens in real time (closes #41)

## Problem

In capture inputs (`CaptureComposer`, `CaptureDetailPanel`), `#word` only becomes a
styled chip after the user picks a suggestion from the popover (effectively after
Enter). Plain typed `#word` text reads as ordinary serif text, even though the
save-path parser and the filtering sidebar already treat it as a hashtag. The
visual lag is the bug — filtering already works without Enter.

## Approach

Add a tiny TipTap extension (`HashtagDecorations`) backed by a ProseMirror
plugin that scans text nodes on every doc change and applies an inline
decoration (`<span class="hashtag-chip-live">`) around every `#word` match.

- Reuses the same regex (`/(?<![\p{L}\p{N}_])#([\p{L}\p{N}_]+)/gu`) used by
  `parseEditor` / `parseEditorJSON` so the rendered tokens are exactly the
  ones the save path will persist.
- Decorations don't touch the document — they're purely visual — so the
  existing Mention extension, suggestion popover, and `parseEditor` logic
  stay unchanged.
- A new CSS class `.hashtag-chip-live` mirrors the sage register of
  `.hashtag-chip-inline` but uses `display: inline` (instead of
  `inline-block`) so it flows with the text and doesn't disrupt the caret
  while the user is mid-word.

## Tasks

1. Add `apps/web/components/captures/hashtag-decorations.ts` — TipTap
   extension wrapping a ProseMirror decoration plugin.
2. Add `.hashtag-chip-live` rule to `apps/web/app/globals.css`, sibling to
   `.hashtag-chip-inline`.
3. Wire `HashtagDecorations` into the `extensions` array of
   `CaptureComposer` and `CaptureDetailPanel`.

## Verify

- Type `#idea` in either capture input — the token visually highlights as
  soon as at least one character follows the `#`, without pressing Enter.
- The token unhighlights on backspace back to the `#` alone.
- Committing a tag via the popover still works (mention nodes keep their
  existing `.hashtag-chip-inline` styling; decorations don't double-style
  them because the doc text inside a mention node lives in `node.attrs`,
  not as a text node).
- `pnpm --filter web typecheck` and `pnpm --filter web lint` pass.
