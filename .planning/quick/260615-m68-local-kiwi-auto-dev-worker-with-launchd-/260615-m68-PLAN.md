Output: Ten committed scripts/docs plus a .gitignore update. These are standalone shell + Node ESM scripts (no app dependencies; node built-ins + gh + git only). NOTHING runs automatically until install.sh is run by the user; the executor only creates and commits the files.

Create the orchestrator as a zero-dependency Node ESM script (`#!/usr/bin/env node`). Use only node built-ins (node:child_process, node:fs/promises, node:path, node:os, node:url) plus the `gh` and `git` CLIs via spawn/execFile. Flow:
1. Re-check the gate by spawning ./gate.sh; if it exits non-zero, log a single line to stderr and exit 0 quietly.
2. `git fetch origin main` (execFile, cwd REPO_ROOT).
3. List eligible issues: `gh issue list --repo $REPO_SLUG --state open --label $LABEL --json number,title,labels`. Sort oldest-first by issue number ascending (lowest number is oldest), take up to MAX_ISSUES.
4. For each selected issue, run IN PARALLEL bounded to MAX_ISSUES (Promise.all over the selected set, which is already capped at MAX_ISSUES so no extra pool needed):
   - Compute UTC date once at run start: const RUN_DATE = new Date().toISOString().slice(0,10).
   - branch = `${BRANCH_PREFIX}/${RUN_DATE}-issue-${N}`; worktreeDir = `${REPO_ROOT}/.kiwi-auto/worktrees/issue-${N}`.
   - Create the worktree: `git worktree add <worktreeDir> -b <branch> origin/main`.
   - Build PROMPT (a single string) instructing headless Claude to: resolve GitHub issue #N ("<title>") for this repo using the GSD quick pipeline (invoke /gsd:quick) with atomic commits, referencing "Closes #N" in a commit; for THIS invocation disable inner GSD worktree isolation (set workflow.use_worktrees=false) so it commits directly on the current branch with no nested worktrees; NEVER run `git push` and NEVER run destructive git (no `reset --hard`, no push, no remote changes); if the issue is too large, architectural, ambiguous, or risky to do safely in one bounded session, DO NOT attempt it, leave the branch untouched, and instead write a skip recap explaining why; when done or skipped, write a per-issue recap to .kiwi-auto/ISSUE-<N>-recap.md (relative to the worktree) and commit that recap on the branch. (Write the prompt in plain prose; remember NO em/en dashes.)
   - Spawn the child with child_process.spawn: command `claude`, args [`-p`, `--dangerously-skip-permissions`, `--model`, MODEL, PROMPT], cwd=worktreeDir, env={...process.env, KIWI_AUTOMATION:"1"}, detached:true (new process group so we can signal the whole tree), stdio piped to a log file stream at tools/kiwi-autodev/logs/<RUN_DATE>-issue-<N>.log (open the file with fs createWriteStream; pipe child.stdout and child.stderr to it). Keep --dangerously-skip-permissions and MODEL exactly as specified (explicit user choices).
   - Enforce PER_ISSUE_TIMEOUT_MS in Node: a setTimeout that, on expiry, kills the child process GROUP via process.kill(-child.pid, 'SIGTERM') then, after a short grace, process.kill(-child.pid, 'SIGKILL'); wrap in try/catch (the group may already be gone). Mark that issue "timed-out". Clear the timer when the child exits normally.
   - Per-issue isolation: wrap each issue's whole lifecycle in try/catch so one failure never aborts the run. Classify the outcome:
       * "timed-out" if the timeout fired;
       * else "failed" if the child exited non-zero with an error AND no commits exist beyond origin/main;
       * else "done" if commits exist beyond origin/main (`git -C <worktreeDir> rev-list --count origin/main..<branch>` > 0) AND the recap (if present) does not say it skipped;
       * else "skipped" (recap indicates a skip, or no code commits were produced).
     Read .kiwi-auto/ISSUE-<N>-recap.md from the worktree if present to capture recap/skip text and to disambiguate done vs skipped.
   - commitCount = integer from `git -C <worktreeDir> rev-list --count origin/main..<branch>` (default 0 on error).
5. After all issues settle: aggregate every per-issue recap into `${REPO_ROOT}/.kiwi-auto/recap-${RUN_DATE}.md` (the main working copy, gitignored). For each issue include: branch, issue number + title, status, commitCount, and the recap/skip text. Then add a "Branches ready for review" section listing each "done" branch with a `git checkout main && git merge <branch>` hint line.
6. Clean up worktrees: `git worktree remove --force <worktreeDir>` for each; KEEP the branches (never delete branches).
7. REPORTING (best-effort): resolve the secret from process.env.DEV_RUN_INGEST_SECRET, else parse DEV_RUN_INGEST_SECRET out of apps/web/.env.local using the inline dotenv parser. If no secret is found, log a warning and skip reporting (do not fail the run). Otherwise POST to `${REPORT_URL}/api/dev-runs` with headers Authorization: `Bearer ${secret}` and Content-Type application/json, using global fetch. Body: { runDate: RUN_DATE, startedAt, finishedAt, status, items }, where startedAt/finishedAt are ISO strings (new Date().toISOString()), status is "ok" if every attempted issue is done or skipped, "failed" if all attempted issues failed/timed-out, else "partial"; items is an array of { issueNumber: N, title, status, branch, branchUrl: `https://github.com/${REPO_SLUG}/tree/${branch}`, commitCount, note } (note = trimmed recap/skip text or short failure reason). A non-200 response or a thrown fetch error logs a warning and does NOT fail the run.
8. Fire a macOS notification via execFile osascript: `osascript -e 'display notification "<done> done, <skipped> skipped, <failed> failed" with title "Kiwi auto-dev"'`. Best-effort (swallow errors).
9. Write the date-stamped lock LAST: ensure `${REPO_ROOT}/.kiwi-auto/` exists, then write `${REPO_ROOT}/.kiwi-auto/.last-run-${RUN_DATE}` (content can be the finishedAt ISO timestamp). IMPORTANT: the lock write, the recap write, and the report attempt must all happen even on partial failure (wrap the main per-issue work so that whatever settled still flows into recap + report + lock).

Do NOT actually invoke `claude`, run install.sh, load launchd, or push during this task; you are only creating the script.
