# Scout α — implementation deep-dive (condensed; full report in conductor transcript)

Architecture: legacy HUD DOM (apps/desktop/src/main.ts) owns the transcript; React Studio (src/studio/**) owns widgets/gestures. In-widget web content = Tauri native CHILD WEBVIEWS (studio_webview.rs, one per widget id, OS-level siblings above host DOM, not in the HUD z-stack).

Root causes (confirmed):
1. TRANSCRIPT: main.ts:183-332 single-pair state machine (turnPairState, one jarvisTurnAwaitingUser slot, single currentReplyBody global). Overlapping turns (partial-utterance turn + full-question turn, independent turnIds from transcript/route.ts) interleave → DOM insertion order inverts. No turnId keying; timestamps cosmetic. FIX SEAM: key bubbles by turnId (available on bridge.ts:95-107 events).
2. DUP WIDGETS: dedup is per-turnId LRU (browser-router.ts:33-87). Two server turns for one spoken query (wake-probe rolling tails + utterance-routine interception firing on partial, normal turn on full) → two buckets → two browsers. Also studio-action path has no turnId (__no_turn__ bucket, studio-action-router.ts:33-37) vs materialize.ts:87 passes turnId → buckets diverge.
3. OVERFLOW: window.open popups from child webviews are entirely unmanaged (no new-window handler in studio_webview.rs) → full-size OS webview over HUD. Secondary: hand-driven resize bypasses useNativeWebviewSync hide-on-pointerdown (native-webview.ts:129-162) since gesture path calls resizeWidget() directly → child bounds lag.
4. IN-WIDGET POINTER: delivery is 100% synthetic DOM events at document.elementFromPoint (pointer-synth.ts:104,125-161,441-458) → hits inert placeholder [data-native-webview-active]; child webview never sees clicks. Only scroll has an IPC bridge (studio_webview_scroll, studio_webview.rs:159-172, does window.scrollBy — fails on custom scroll containers). enigo in Cargo deps but UNUSED for HUD. No click IPC exists.
5. CLICK-AS-MOVEMENT: palm-click DOES anchor at lastCursor (gesture-core.ts:964-970) but pose flip needs debounceFrames=3 agreeing frames — during curl the hand is still 'open/point' so the inward-moving fingertip keeps driving moveCursor (~100ms drift baked into aim). Smoothed openness widens the window.
6. SCROLL: (a) native target resolved once at scrollStart, requires [data-native-webview-active]; pre-promotion → DOM wheel onto placeholder = nothing; window.scrollBy fails on custom containers. (b) scroll-curl gate nearly unsatisfiable: 250ms sustain in openness band [1.35,1.6) + minVelocity 0.9 → tiny engagement region; hub drops lifecycle when hover null (hub.ts:344-357).
7. RESIZE: resizeEngageAllowed false when openness<1.35 or clickClosing (gesture-core.ts:504-512,918-928) — shrinking a widget looks like a palm-click onset → disarms. Plus armMs=300 dwell, heavy rate-limit (maxScaleStepPerMs=0.004), and the U3 bounds-lag makes it look broken. Resize is CUMULATIVE from armed w0/h0 baseline.

Invariants: widget-windows.ts single writer via write(); drivers targetless, hub sole hover resolver; per-turn URL LRU only spawn guard, openBrowserUrl sole URL summon site; data-native-webview-active sole DOM-vs-IPC discriminator; child bounds derive only from [data-native-webview-content]; palm-click/scroll-curl/resize gates interdependent (gesture-core.ts:473-512,918-970); SYNTH_POINTER_ID=90210 capture shim must stay; one labeled child webview per widget id.
